# Heirloom Ledger — 第一章《旧账未清》

Godot 4 隔离可玩原型。正式设计仍为 draft/review，本轮参数不自动成为 locked 规则。

## 开始试玩

1. 双击本目录的“开始试玩.cmd”。默认启动第一章，不再进入旧单日演示。
2. 在连接页填写服务商的 Base URL、Endpoint、协议、模型和 API Key。表单可以向下滚动。
3. “继续已有章节”默认在有存档时勾选；取消勾选会开始新章并覆盖旧进度。
4. 点击“连接并开始营业”。它会先测试连接，再生成开场对白。也可以先点“测试连接”，但会多一次请求。

测试连接与正式对话均会请求你填写的服务，可能产生服务商费用。自动测试只使用本地模拟服务；历史受限真实联调见验收记录。没有有效配置会明确报错。

连接页填写配置名称后点击“加密保存此接入配置”，API Key与参数使用Windows当前用户保护保存，重启恢复。不同名称可保存多份配置，设置里点击“切换到…”即可切换，下一句生效；请求进行中不能切换。相同名称保存会更新该配置，“删除本机已保存凭据”会删除全部已存配置。旧单配置自动作为“原有配置”读取。配置不进入游戏存档。

连接页有 Kimi Code 模板：Base URL `https://api.kimi.com/coding/v1`，Endpoint `/chat/completions`，Chat 协议，模型 `kimi-for-coding`；需填写对应平台的Key。Kimi官方将Code定位为编程服务，游戏产品集成应核对账户适用范围；Kimi开放平台使用 `https://api.moonshot.cn/v1` 和独立Key。本轮未进行Kimi真实调用。参考：[Kimi官方接入与平台对照](https://www.kimi.com/code/docs/en/)。

## 场景与交谈改版

默认进入 `immersive.tscn`。开场有可跳过的序章、信件与旧照，之后可从桌上笔记重读。

- 双方对白有姓名、头像和左右消息卡；私人判断显示在独立卡片并收进笔记，结算记录收进账本。
- 右上角齿轮集中设置、保存/读取、返回接入配置。货架看库存，门口外出，两本书分别是账本与调查笔记；热点悬停时会在鼠标附近显示用途，也可用键盘聚焦。
- 对话区可收起；会面资料、当前状态和历史开关固定在对话区上方。经营记录、剧情调查、人物往来、器物判断在笔记中分栏显示。
- 会面资料、快捷提问、剧情正事和回答参考默认收进抽屉；等待模型时显示“正在思考”，完整回复到达后逐字呈现，玩家发言使用更快的逐字效果。聊天在新增消息和显示过程中自动跟随到底部。
- 市场有4家固定老店、每日3～5个临时摊位，各5～8件在售货。在场景中点击金色描边店铺/摊位；悬停预览简介、主营及推荐品。进入后用大面积三列网格陈列，主营外兼有少量其他类别。
- 商品详情顶部可主动复核、输入整数报价并还价；收购前需鉴定，谈妥后确认交割。上午结束与闭店后，屏幕底部独立显示流程推进按钮，收起交谈也不会隐藏它。
- 可输入“我出700元”等明确议价句，报价输入支持个位整数；价格谈妥后点击“确认钱货交割”。退出重入不会重置当天话题、耐心或物件。
- 夜间可与已认识的人交谈，从库存选择物件后“拿给对方一起看”；私人鉴定不会自动公开。许闻溪专业复核沿用既有收费与每日限制。
- 拍卖从第三日起开放：每场 6～8 件图录，可在预展查看并标记关注；入场后逐件显示拍卖师状态与 2～4 名可观察竞买人，可举牌、放弃本件或提前离场。成交价、5%费用和物权转移均由 Game Core 结算。
- 调查笔记按实际线索更新疑问、已核对事项和可走访方向；每个剧情相关 NPC 都会在会面中显示对应的剧情情境提问快捷按钮，按钮只提出问题，不自动替玩家选择剧情分支。

真实模型联调已授权累计人民币10元上限。本机已保存受保护接入配置并完成受限连接测试；默认自动测试仍使用本地替身，实际模型对白质量仍需继续验收。

## 参数怎么填

- Base URL：服务的API根地址；以服务商说明为准。
- Endpoint：追加在根地址后面的接口路径。Responses通常是 `/responses`；Chat Completions通常是 `/chat/completions`。不要把完整地址再重复填在Endpoint里。
- 协议：决定发送和解析哪一种JSON格式，必须与Endpoint相符。
- 模型：服务商账户实际可用的模型标识，不是聊天产品的显示名称。
- Temperature：措辞变化程度。本版本仅在Chat协议发送；默认留空、不发送，更适合先排查兼容性。服务支持时可以填0.7，越高通常措辞变化越大；它不改变游戏真伪、价格或成交规则。
- 最大输出Token：默认2048，实际按输入值发送，不再暗中限制为220。推理模型的思考也可能占用输出预算；出现截断时按服务说明调整。
- 超时：默认45秒。生成速度不推进游戏时间。
- Chat Token参数、额外Header、Organization、store=false：仅按服务商要求填写/开启。不要把不需要的兼容选项全部打开。

若环境设置了HTTP_PROXY/HTTPS_PROXY，游戏使用该代理；本地127.0.0.1/localhost测试地址直连。额外Header会发送到你指定的服务，请只填写该服务需要的信息。

## 一天怎样经营

上午两位来客 → 午间整理/外出 → 下午两位来客 → 闭店小记 → 下一日。没有精确时钟或行动点，看资料不扣耐心。

- 卖家：听来意 → 观察、问来历/修补/动机 → 必要鉴定 → 对话报价或放弃 → 确认交割。没鉴定不能收购，资金不足不能结算。
- 买家：问类别、用途、预算 → 点击货架选物 → “拿到柜台，向客人推荐” → 查看物件资料 → 点回答参考，编辑后发送 → 报价或不成交。
- 提示不是标准答案：区分卖方陈述、已经看到的线索、当前概率和未知内容。NPC的隐藏预算、动机和权威真伪不会进入事实卡。
- 查看资料与必要回答免费；追问新主题消耗耐心，重复追问更快。耐心耗尽仍可以完成必要私下鉴定、给出最后报价或结束。
- 推荐后输入“报价1500”或“不卖了”可以表达明确交易意图。复杂自由文本仍是有限的本地识别，正式成交建议用明确按钮。

## 第一章内容

10日、8位重要人物反复来访、28件独立道具、旧账证据与3类收束。章节围绕爷爷留下的寄存记录展开：照片、交接人与原主不是同一回事，缺证据不强行拼结论。

柜台场景可点击货架、账本、台面和门口。库存、知识笔记、人物往来、交易账本可随时查阅。午间和闭店后可外出：

- 古玩街：有限批次看货、议价补货，反复进出不刷新物件。
- 许闻溪工作室：每日报告一次，¥100；瓷器与书画专长更高，超出她的帮助范围不收费。
- 小型拍卖：第三日起预展、举牌、被跟价或退出；成交加5%费用，一次结算。章内为有限拍品。
- 经营恢复：低资金且无可售物件时提供基础看货委托；寄存物不会把恢复入口堵住。

库存复核随分类知识成长解锁证据；未判假时为1～99整数概率。售出假货不当场揭露，后续具体看货发现可能引发知识增长、关系和信誉损失，再按身份、售价扩散。已知反馈在旧账页可沟通；不自动退款。

“旧物归人”和“有据可循”需要相应证据，按钮会显示尚缺条件。委托收束中固定授权成交¥1800、原主收¥1620、店铺服务费¥180，单列在账本，不凭空把寄存品变成自有资产。

## 保存与错误恢复

每句成功回应、阶段结束及安全操作后自动存档，也可手动保存。存档为同一文件中的Core状态与对话视图，临时文件写完后替换；保存失败会提示。

用户数据目录保留旧应用名以兼容：
`%APPDATA%/Godot/app_userdata/Heirloom Ledger — 一日试营业/`

- `chapter_save.json`：第一章进度，不含API配置。
- `llm_diagnostics.jsonl`：HTTP状态、耗时、协议、Token预算和终止原因等白名单元数据，不记录请求头、Key或原始回复。
- `logs/`：Godot运行日志。

对白失败时新交易操作冻结，“重试这一句”只重发对白，不再次扣钱、给物件或消耗耐心。需要更换配置时打开“设置 → 返回API配置”，取消当前网络请求并保留内存中的交易结果；重新连接后继续原句。未完成的回应不写入新安全存档，异常关闭会回到最后成功保存处。

## 已知边界

- 尚未验证你所用模型的真实措辞、角色遵从和端到端延迟；不能承诺所有兼容网关都可直接工作。
- 这是固定第一章，不是无限生成的开放世界。店外机会有限，事件分支、知识门槛和市场报价仍需试玩调平。
- 粗略估价是原型启发式，不是专业估值；照片为美术插画，文字记录才是可用线索。
- 同类道具部分共用24格物件图；当前人物和器物使用透明化处理后的图集，但仍需继续检查个别格子的边缘质量。人物目前是单立绘，没有完整多表情图集。已接入市场、茶馆和旧照插画；各商户暂共用市场背景。
- 真实玩家存档损坏、系统权限和特殊代理配置仍需现场验证。不要把重要进度只保留一份。
