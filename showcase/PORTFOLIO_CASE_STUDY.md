# Heirloom Ledger｜项目作品集介绍

## 项目概述

**Heirloom Ledger｜藏珍账**是一款叙事型古玩店经营游戏原型。玩家从大城市回到故乡，接手爷爷留下的古玩店，在经营、鉴定、交易和人物往来中，逐渐发现一批没有价格、只写着“暂存”的旧物背后，牵涉的并不是一个简单的寻宝答案，而是保管、授权、记忆和责任。

本次展示聚焦第一章《旧账未清》的 Godot 可玩原型：10 个章节化营业日、8 名重要 NPC、28 件器物数据，以及古玩街、专家拜访和小型拍卖等店外机会。

## 我想解决的问题

古玩经营题材很容易变成“点按钮看数值”。这个项目把核心体验放在“通过交谈识人，在不完整信息中作判断，并为结果负责”上：

- 玩家先听客人的说法，再结合物件线索、来源记录和自己的知识作判断。
- 鉴定给出证据和不确定性，不直接替玩家宣布标准答案。
- 议价、库存和资金让一次判断产生持续影响。
- 旧账、照片、存根和人物记忆让经营行为逐渐汇入一条可追溯的故事线。

## 代表性体验

### 1. 场景就是菜单

店铺中的货架、账本、调查笔记和门口都成为可点击的场景热点。玩家通过“走到哪里、查看什么”建立自己的调查节奏，而不是从一排抽象文字按钮开始。

### 2. 对话、私人判断和经营记录分层

公共对白、掌柜的内心判断、人物往来和交易结算被放在不同的信息层。这样既保留人物对话的自然感，也避免把玩家尚未说出的推断直接塞进 NPC 的嘴里。

### 3. 物件判断承认不确定性

玩家可以查看卖方说法、已知线索、历史判断和当前资料，再决定是否鉴定、收购、推荐或放弃。判断结果不会因为界面给出一个数字就自动变成绝对真相。

### 4. 经营行为会留下关系与故事后果

库存、资金、知识、人物记忆、关系和剧情旗标跨日保存。玩家可以选择归还旧物、取得授权后委托出售，或在证据不足时保留未决事项继续经营。

## 系统与实现思路

- **引擎**：Godot 4 原型。
- **内容结构**：章节、器物、角色和事件采用数据驱动；原型内容集中在第一章数据中。
- **状态边界**：Game Core 保存资金、库存、判断、关系、记忆和剧情状态；LLM（若启用）只负责依据已有状态表达对白，不直接修改权威世界状态。
- **可靠性**：本地测试覆盖跨日存档、物权与资金的一次性结算、外出机会不重复刷新、两类 API 协议夹具、空正文、截断、超时和重试不重复结算。
- **美术方向**：中式写实插画，使用店铺、古玩街、茶馆、人物和器物图集构成可玩的场景层。

## 我的设计取舍

我刻意把“没有足够证据”保留为一种有效结果。章节的三种收束不是简单的善/恶/财富分支，而是三种对证据和处分权的态度：归还、在授权与说明完整后处理，或承认尚不能下结论。

同时，作品集展示会把“原型已经验证的内容”和“仍需真人试玩验证的内容”分开：当前页面展示的是本地可玩流程、界面结构和数据边界，不把模拟对白包装成已经完成的模型体验。

## 当前状态

这是一个可玩的第一章展示原型，仍处于 pre-production / design foundation 阶段。下一步重点是继续收集真实试玩反馈，打磨剧情节奏、对话自然度、跨会面记忆和经济平衡，再决定哪些原型参数进入正式生产方案。
