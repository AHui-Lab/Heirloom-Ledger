# Core Loop

## 1. Purpose

Core Loop 的首要目的，是让玩家通过自然交谈判断客人是否可信、理解其表面需求，并推测对方尚未直接说明的真实意图。对话不是单纯的叙事包装，而是玩家获取交易信息、判断人物和作出经营决策的主要玩法渠道。

在信息始终不完全可靠的情况下，玩家还需要结合器物线索、自己的知识与经验、客人的说法、报价和当前经营状态作出决定，并承担捡漏、打眼、买贵、错过机会或损害关系的后果。

其他核心体验围绕这一判断过程服务：

- 鉴定提供判断器物真伪与价值的专业证据，但不保证绝对正确。
- 议价把玩家对人物与物件的判断转化为可承担的交易选择。
- 资金和库存让错误判断产生持续的经营后果。
- 知识、经验与人脉成长让玩家能够理解更深的信息、接触更复杂的人和交易，而不只是提高数值。
- 爷爷的故事与人物关系为长期经营赋予情感和探索目标。

如果移除这一循环，游戏将失去“通过交谈识人、在不确定信息中判断并为结果负责”的核心体验，只剩下缺少人物判断与风险张力的数值经营。

Game Core 必须预先保存客人的权威状态、可信程度、已知信息和真实意图；LLM 只能依据这些状态自然地表达客人的说法、隐瞒、犹豫和反应，不能临时创造或改变真相。

## 2. Core Loop Summary

用一行描述游戏的最小核心循环：

```text
[进入店铺营业]
→ [Game Core 安排当天来客]
→ [客人自动到访]
→ [玩家通过对话发现客人需求]
→ [进入卖货或买货分支]
→ [完成、拒绝或放弃本次交易]
→ [继续接待当天其他客人]
→ [当日来客处理完毕]
→ [结算当日经营结果]
→ [结束营业]
```

## 3. Loop Hierarchy

## 3.1 Micro Loop：单个客人交互

Micro Loop 描述玩家接待一名客人时经历的完整交互。

客人的来意在到访前已经由 Game Core 确定，但不会在客人出现时直接显示。玩家需要先与客人交谈，才能发现对方是来卖货还是买货。

### Micro Loop Summary

```text
[客人到访]
→ [玩家与客人交谈]
→ [发现客人来意]
├─ [卖货分支：鉴定来货 → 判断与议价 → 收购或放弃]
└─ [买货分支：了解需求 → 推荐库存 → 更新判断 → 出售、议价或拒绝]
→ [结算本次交互]
→ [客人离店]
```

### Micro Loop Start

一名客人到达店铺时开始。

### Micro Loop End

本次交易完成、被玩家拒绝、被 NPC 拒绝或被双方放弃，并完成相应状态结算后结束。

普通买货交易一旦完成，即视为钱货两清。本次 Micro Loop 不再触发交易后二次鉴定、退款或交易撤销。

如果玩家卖出的物件真实状态为假，交易完成时不会立即扣除信誉或向玩家揭示真相。只有该物件以后在二次倒卖、被其他人看货或类似场景中被真实识别为假时，才进入后续影响判定；成交价格不影响问题能否被发现，只在真实发现后与其他因素一起影响是否产生信誉、口碑或关系影响，以及影响程度。交易本身仍不退款、不撤销。

假货被发现时，玩家也会获得与被发现瑕疵相关的知识或经验，使失败成为学习来源。

同样，如果玩家在出售时对物件的年代、来源、真伪等客观属性作出错误陈述，交易完成时不立即揭示或处罚。只有该陈述与客观事实在后续流转、看货或类似场景中被真实发现时，才可能触发信誉、口碑、关系或事件后果；第一版不在交易当下强行区分玩家是正常误判还是故意欺骗。

后续发现者暂采用三个能力层级：普通客人只能发现非常明显的问题；懂行买家或相关 NPC 能发现较隐蔽的问题；专业鉴定人拥有最高的相关发现能力。实际能否发现仍由 Game Core 结合物件问题、发现者能力和发现情境结算，不保证高能力者每次都发现。

## 3.2 Short Loop：一日营业

Short Loop 描述玩家从开始营业到结束当天营业的完整循环，其中会重复执行多个 Micro Loop。

### Short Loop Summary

```text
[开始一天营业]
→ [查看当日开场信息]
→ [接待上午来客并重复单客 Micro Loop]
→ [午间过场与自由查阅]
→ [接待下午来客并重复单客 Micro Loop]
→ [晚上闭店并结算经营结果]
→ [出现剧情余韵或下一日线索（如当日有）]
→ [进入下一营业日]
```

### Short Loop Start

一次 Short Loop 从玩家进入店铺并开始当天营业时开始。

### Short Loop End

当当天计划到访的客人全部处理完毕，并完成当日经营结算后，Short Loop 结束。

### Daily Visitor Range

当前暂定每天自动到访：

- 卖货客人：2～3 名
- 买货客人：2～3 名
- 上午来客：2～3 名
- 下午来客：2～3 名
- 每日总计：约 4～6 名

具体人数由 Game Core 在范围内决定，并可以受到全局信誉、相关类别口碑、公开展示、历史成交表现和 NPC 关系影响。买货客人不会直接知道店内隐藏库存。

剧情客人、后果回访客人和其他特殊客人默认计入每天约 4～6 名客人的接待总量，而不是在常规来客之外额外增加。Game Core 根据其权威来意，用其替代当天一名同类常规客人，以继续维持卖货客人与买货客人各约 2～3 名的日常结构。只有被 Game Core 明确标记的重要剧情例外，才可以突破当日常规接待总量。

Game Core 同时控制买货与卖货客人的全日到访顺序。普通情况下最多连续出现 2 名同类客人，不得连续安排 3 名买家或 3 名卖家；上午与下午的阶段切换不会重置连续计数。剧情或经营主题确有需要时，可以由 Game Core 显式标记受控例外，LLM 不得自行改变来客顺序或制造例外。

该人数范围属于 draft 平衡参数，后续可根据节奏和试玩调整。

### V1 Day Structure

V1 使用章节化营业日，不模拟连续流逝的精确时间，也不设置可见行动点。上午、下午和晚上是按营业流程依次进入的阶段节点：上午来客处理完毕后进入午间过场，玩家确认继续营业后进入下午；下午来客处理完毕后进入晚上并闭店结算。单客交互不会因为玩家现实中的阅读或思考时间而受到惩罚。

标准营业日的上午和下午各安排 2～3 名客人：4 名时为上午 2 名、下午 2 名；5 名时一段 2 名、另一段 3 名；6 名时为上午 3 名、下午 3 名。5 名客人时由 Game Core 根据当天买卖组合、剧情、经营主题和节奏决定哪一段安排 3 名。买货与卖货身份只要求全日各约 2～3 名，不要求每个阶段拥有固定类型配额。晚上不安排普通来客，也不提供外出、拍卖或正式学习玩法，只用于当日结算、剧情余韵和下一营业日的线索。

剧情客人、后果回访和其他特殊客人优先占用上午或下午的标准名额。只有被 Game Core 明确标记的重要剧情例外可以突破单阶段 2～3 名和全日约 4～6 名的标准结构；该例外不得由 LLM 自行增加。

午间过场是节奏分隔，不是需要计算成本的经营回合。玩家可以自由查看库存、账本、历史交易、人物已公开资料、已有鉴定记录和其他已解锁信息，然后主动确认进入下午。此类查阅不会减少来客数量或改变时段。

### Visitor Content Composition

每日来客除了买货或卖货身份，还可以由 Game Core 标记为常规经营、判断挑战、剧情锚点、后果回访或经营恢复等内容职责。同一名客人可以同时承担交易身份和剧情职责，例如一名卖货客人也可以是剧情锚点，一名买货客人也可以带来过去交易的后果。

除教学日或被 Game Core 明确标记的经营恢复日外，每个标准营业日至少需要包含 1 名承担“判断挑战”职责的客人。判断挑战不是固定的骗子、高价值物件或必然获利机会，而是要求玩家结合交谈、器物线索与经营状态作出有意义判断的案件。它可以来自客人说法与器物线索之间的不一致、客人真诚但错误的认知、买家隐藏的用途或真实预算、库存只有弱匹配候选，或高收益同时伴随较高打眼风险等情况。

普通标准营业日安排 1～2 名判断挑战客人，不应让当天全部 4～6 名客人都承担判断挑战。教学日和明确的经营恢复日允许没有判断挑战；重要剧情日确有需要时最多可以安排 3 名，但必须由剧情数据明确声明例外。具体强度和类型仍需通过营业日样例与试玩调整。

“判断挑战”及其具体来源属于隐藏内容标签，不向玩家直接显示，也不使用特殊图标或提示宣告本次客人是考题。Game Core 必须在客人进入交互前确定挑战来源、至少一项玩家有机会发现的有效线索、能够利用该线索的相关行为，以及可能产生差异的结果分支。有效线索不保证玩家必然发现，也不保证发现后得到完全确定的答案；玩家的知识、经验、提问方式和交易选择仍然影响结果。但判断挑战不能被设计为没有依据的随机猜测、无论玩家如何行动都必然失败，或由 LLM 在交谈中临时编造矛盾。

V1 采用“设计者编排重要剧情节点，Game Core 生成或选取常规经营案件，LLM 表达具体交谈”的组合。剧情推进不要求每天必然发生：剧情客人、消息、旧交易回访或爷爷线索可以隔数日出现，也可以因剧情进入关键阶段而连续数日出现。Game Core 只根据已经定义的事件条件与内容安排触发，不以“每天必须有剧情”为硬性配额。

### Daily Business Theme

没有重要剧情推进的纯经营日，应由 Game Core 选择一个数据化的当日经营主题，使当天在来客构成、器物类别、交易动机、市场话题或整体氛围上形成可感知的差异。例如某日瓷器询价者增多、近期有人集中出手民国器物，或市场开始关注某个价格区间。剧情日也可以拥有与剧情兼容的经营主题，但不作强制要求。

经营主题通过调整候选来客和案件的生成权重发挥作用，不直接生成必然结果。它不能保证某类物件更赚钱、保证出现捡漏、改变已经生成的器物真相或 NPC 隐藏状态，也不能替玩家判断应当买卖什么。每日仍需遵守约 2～3 名卖货客人、2～3 名买货客人及 Game Core 控制到访节奏等基础结构。

经营主题采用两类来源并可组合：

- **世界驱动：** 来自已经成立的市场趋势、城市传闻、行业事件、季节性需求或剧情阶段。
- **玩家驱动：** 来自玩家已经对外形成的类别口碑、公开陈列、历史成交表现、NPC 关系和已经传播的事件结果。

玩家驱动不等于系统读取玩家全部内部状态。买家不知道店内隐藏库存，因此未公开的库存构成不能直接提高对应买家的到访概率；尚未被发现的真假问题、未传播的交易事实和其他隐藏信息，也不能产生外界本不可能知道的主题。玩家行为可以同时吸引机会与风险，例如瓷器口碑既可能带来寻找瓷器的买家，也可能带来试探玩家水平或试图高价出货的卖家，不应自动成为正向奖励。

普通公开交易只累积与相应器物类别、价格层级或经营表现有关的对外信号，不因单笔普通成交立即形成新的经营主题。相关信号达到尚待确定的门槛后，才可以成为后续玩家驱动主题的来源。与重要 NPC 的公开成交、相对当前经营层级显著的高价值交易，或已经形成公开传播的重大事件，可以立即使相应来源获得主题候选资格。这里的“立即”只表示可以影响下一个尚未生成的营业日，不得事后改写当天已经生成的来客和案件。

类别口碑由 Game Core 按器物类别保存精确内部状态，但不向玩家显示数值、进度条或下一阶段门槛。玩家只看到四个模糊阶段：**尚无名气、偶有人提起、逐渐形成口碑、在相关圈子里受到认可**。阶段变化通过当日开场、闭店摘要、市场传闻和 NPC 对话反馈；单次微小数值变化不要求逐笔提示。

V1 将以下三类社会评价作为独立但可受控联动的权威状态：

- **类别口碑：** 外界认为玩家是否经常经营、擅长某类器物，按器物类别分别记录。
- **全局信誉：** 外界对店铺整体可靠性与诚信程度的评价，不绑定单一器物类别。
- **NPC 关系：** 某个具体人物对玩家的信任、态度和共同经历，按 NPC 分别记录。

全局信誉由 Game Core 保存精确内部状态，但玩家只看到四个模糊阶段：**声誉受损、尚无定论、口碑稳定、值得信赖**。不显示精确值、进度条、阶段门槛或距离下一阶段的进度。变化通过店铺状态、营业日开场与结算、市场传闻和客人态度表现。

NPC 关系同样由 Game Core 按具体人物保存精确内部状态，但玩家只看到五个统一阶段：**防备、生疏、熟悉、信任、深交**。五个阶段的机械含义保持一致，不同 NPC 根据性格、身份与表达习惯呈现不同的言语和行为；外向人物在“熟悉”阶段可能表现热情，克制人物即使进入“信任”阶段也可能少有直接表态。玩家不查看精确值、进度条和阶段门槛。

关系阶段只是当前人物态度的概括，不取代 NPC 的具体记忆、承诺、利益冲突和社会连接。Game Core 仍需独立保存重要互动与事件记忆；达到“信任”或“深交”不会自动抹除负面记忆，也不保证 NPC 在所有事件中无条件帮助玩家。

一次交易或事件必须分别声明影响其中哪些状态以及原因，不能用一个统一“声望值”同时加减三者，也不能根据其中一项自动推导另外两项。已售假货被真实发现后，可能只影响原买家的关系，也可能在传播后影响相关类别口碑或全局信誉；具体范围由 Game Core 根据发现内容、涉及类别、买家身份、关系对象和传播圈层分别结算。玩家可以出现类别口碑较高但全局信誉较低，或某名 NPC 信任玩家但市场整体尚未认可的状态。

玩家应通过当日开场信息、市场传闻、客人谈话或来客构成感知主题，而不是看到完整后台倍率或最优策略提示。LLM 可以根据 Game Core 提供的主题与授权影响表达氛围和相关说法，但不能自行创造主题、扩大其效果或把模糊趋势说成确定事实。

玩家在当前客人交互尚未结束时，可以暂时切出对话界面，查看本次判断需要的库存、账本、人物资料和鉴定记录，再通过可识别的头像、柜台卡片或等价入口返回。Game Core 保留对话历史、已公开信息、耐心和交易阶段；界面切换不消耗耐心，也不结束交易。同一时间仍只有一名当前交互客人，尚未出场客人的身份和来意不提前公开。

外出、拍卖、拜访 NPC、正式学习、预约冲突、耗时店内活动、中断恢复和连续时间成本均不属于当前 V1 Core Loop。相关构想保留为后续版本候选，不用于约束 V1 设计与实现。

## 3.3 Medium Loop

描述玩家在一次经营周期、营业周期或其他中等时间单位中经历的循环。

### Medium Loop Summary

```text
[经营开始]
→ [接待客人 / NPC]
→ [进行交易或活动]
→ [获得收入、信息或机会]
→ [结算经营成本]
→ [进入下一经营周期]
```

### Time Unit

Medium Loop 由多个营业日组成；其准确周期长度仍待决定。

## 3.4 Long Loop

描述玩家通过长期经营、成长、人脉和故事推进形成的循环。

```text
经营店铺
→ 学习知识并积累实际经验
→ 建立 NPC 关系与行业人脉
→ 获得更高层级机会
→ 接触更复杂的器物与事件
→ 了解爷爷的故事
→ 形成自己的收藏与鉴宝人生
```

## 4. Micro Loop and Short Loop Phase Specification

每个阶段都需要说明：Purpose、Trigger、Player Action、Information Visible to Player、Game Core Resolution、Output State、Risk / Failure、Feedback 和 Related Systems。

## Phase 1: 开始营业并安排当天来客

### Purpose

这一阶段为什么存在？

### Trigger

玩家进入店铺并开始当天营业。

### Possible Sources

- 爷爷留下的原始库存
- 玩家发现爷爷隐藏的宝藏
- 顾客带来货物出售
- NPC 在店内提供货源、鉴宝委托、消息或交流机会
- 信件、电话、账本记录或已经发生的交易带来新线索
- 其他：

### Player Action

玩家可以：

- 开始营业
- 查看当前库存
- 查看店铺当前状态
- 查看当日开场信息或昨日遗留提示
- 等待当天第一名客人到访
- 其他：

### Information Visible to Player

玩家可以看见哪些信息？哪些信息暂时隐藏？

### Game Core Resolution

Game Core 根据全局信誉、相关类别口碑、公开展示、历史成交表现、NPC 关系、事件条件和其他有效条件，决定当天实际到访的客人数量、身份、上午或下午分布、内容职责和到访顺序。买货客人不会因此直接获知店内隐藏库存。

到访顺序应由系统控制节奏，避免连续出现过多买货客人或卖货客人。

当前暂定每天生成 2～3 名卖货客人和 2～3 名买货客人。客人的身份必须在到访前确定，不能由 LLM 在对话中临时决定。

### Output State

生成当天章节化营业安排，并进入上午第一名客人的 Micro Loop。

### Risk / Failure

玩家可能承担什么风险？

### Feedback

玩家如何知道这一阶段的结果？

### Related Systems

- [[ANTIQUE_SYSTEM]]
- [[ECONOMY]]
- [[RELATIONSHIP_SYSTEM]]
- [[EVENT_SYSTEM]]

## Phase 2: 客人到访并通过交谈发现需求

### Purpose

让来客从系统生成的状态转化为玩家能够理解和处理的具体需求。

### Trigger

客人自动到访后进入本阶段。客人的买货或卖货身份已经由 Game Core 确定，但玩家尚未直接得知。

### Player Action

- 与客人打招呼并交谈
- 询问客人的来意和需求
- 根据对话决定如何继续回应
- 发现对方是来卖货还是买货

### Information Visible to Player

玩家不会在客人刚出现时直接看到其买货或卖货标签，而是通过对话理解对方的来意。客人尚在等待时，玩家只知道仍有客人在等候，看不到其身份、来意、需求或具体队列顺序。

### Game Core Resolution

Game Core 提供客人的权威身份、需求和相关状态。LLM 根据这些已确定状态表达客人的语言和反应，但不能改变客人的真实来意。

### Output State

识别客人需求后，进入卖货分支或买货分支。

### Risk / Failure

对话可以存在含蓄或自然的表达，但不应让玩家因为系统表达不清而无法进入正确分支。

### Feedback

客人通过后续对话、展示古玩或表达购买需求，使来意明确。

### Related Systems

- [[ANTIQUE_SYSTEM]]
- [[KNOWLEDGE_SYSTEM]]
- [[WORLD_STATE]]

## Branch A1: 卖货客人——观察、询问与鉴定

### Purpose

让玩家在收购前，通过观察器物、询问卖家和使用当前知识与经验形成判断。

### Seller Hidden State

卖货客人不采用五种固定、互斥的类型。Game Core 应通过多个可组合维度表达卖家的真实状态：

- **认知状态：** 不了解物件、错误相信自己的判断、知道部分问题，或较了解物件的真实价值。
- **表达诚实度：** 如实表达、选择性隐瞒，或主动提供虚假信息。
- **出售动机：** 普通变现、急需资金、清理物品、询问行情或其他合理动机。
- **谈判策略：** 直接报价、保守试探、高价试探，或根据玩家表现调整策略。

这些维度可以组合。同一名卖家可能知道物件有价值、急需资金，同时还在试探玩家是否懂行。NPC 的说法与器物真相不一致，也不必然代表故意欺骗：卖家可能只是真诚地相信了错误信息。

具体枚举、组合限制和玩家能够获得的对话线索尚未确定。

### Conversation Patience

玩家不能通过无限发问穷举卖家的所有信息。每名卖货客人在本次交互中拥有由 Game Core 管理的有限交谈耐心或等价阈值：

- 耐心按照 Game Core 验证后的对话行为结算，而不是按照玩家发送的消息条数固定扣除。
- 普通回应、确认和必要澄清通常不消耗耐心；询问新的有效主题正常消耗；重复已经回答的问题，或直接施压、质疑和指控，通常消耗更多耐心。
- 玩家合理引用已有线索进行追问时，可以使用较低或正常消耗，并更有机会获得有效信息。具体消耗等级仍待平衡。
- 单次交谈内不能通过寒暄、夸奖或重复友好表达持续恢复耐心。
- 玩家在冒犯 NPC 后可以尝试一次道歉、解释或主动退让。Game Core 根据 NPC 性格、双方关系和受冒犯程度决定是否接受；成功只恢复少量耐心，且不能超过本次交互的初始上限。
- 长期关系主要影响客人进入交易时的初始耐心，不提供可反复使用的对话内恢复手段。
- 正确追问、相关知识、经验和前后矛盾可以让玩家获得判断线索，但不保证识破所有隐瞒或欺骗。
- LLM 必须依据当前耐心状态表现客人的耐烦、犹豫、警惕或不满，不能自行决定耐心数值或是否耗尽。
- 普通情况下，耐心耗尽后进入“最终报价阶段”：卖家停止回答新的调查问题，要求玩家报价或放弃，但不会仅因耐心耗尽而自动取消交易。
- 最终报价阶段仍允许玩家完成收购与必要的最后议价。若玩家继续追问、施压、指控或拖延，Game Core 可以让卖家结束交易并带走物件。
- 急躁或已经受到冒犯的 NPC 可以更早结束交易，但必须先通过态度变化提供可感知的反馈。
- 不设置能够直接显示“NPC 正在说谎”的万能提示。
- Game Core 可以保存精确耐心值，但不向玩家直接显示数字或进度条。玩家通过 NPC 的态度变化和模糊阶段提示判断剩余交谈空间。

态度阶段的具体数量与命名、各类对话行为的消耗值、一次性挽回的触发条件与恢复量，以及最终报价阶段哪些行为构成继续拖延仍待决定。

### Player Action

- 观察器物
- 询问卖家关于来源、年代和价格的信息
- 根据对话判断卖家提供的信息是否可信
- 使用当前知识和经验进行鉴定
- 查看当前能够获得的真伪、年代、品相和估值信息
- 继续询问或结束调查

### Information Visible to Player

Game Core 先检查玩家是否具备识别器物相关瑕疵的经验：

- 如果玩家能够发现足以判假的明显瑕疵，则向玩家提供“判定为假”的结论及相关线索。
- 如果玩家没有发现足以判假的瑕疵，则根据当前知识、经验、器物难度和已获得线索，向玩家提供 `1%–99%` 的整数真品概率，不显示小数，也不出现 `0%` 或 `100%`。
- 鉴定反馈同时包含基于已发现线索生成的玩家内心独白，用自然语言表现玩家当前为什么产生这一判断以及仍有哪些不确定性。

没有发现假货证据不等于证明物件为真。数值概率由 Game Core 决定；内心独白由 LLM 依据 Game Core 授权的概率、线索和不确定性生成。具体呈现见 [[ANTIQUE_SYSTEM]]、[[KNOWLEDGE_SYSTEM]]、[[LLM_DESIGN]] 与 [[UX_FLOW]]。

主动鉴定期间，每当玩家通过观察、询问或其他行动获得一条有意义的新线索，Game Core 重新计算真品概率并更新允许表达的信息，LLM 据此更新内心独白。

库存中的物件不会因为玩家能力成长而在后台自动刷新鉴定结果。只有玩家重新查看、重新鉴定或向买家推荐该物件时，才根据当前知识、经验和已有线索重新计算。购入时及之后各次鉴定结果都应保留，供玩家比较判断变化。

### Game Core Resolution

Game Core 保存器物真实状态、可识别瑕疵及其所需经验，并决定玩家能否发现决定性瑕疵。未形成明确判假时，Game Core 根据玩家当前能力生成数值化的真品可能性和允许表达的线索集合。卖家的陈述和器物真实状态可以不一致。

### Output State

形成本次收购前的鉴定与估值记录，并进入收购决策。

### Risk / Failure

- 获得不完整信息
- 相信卖家的错误陈述
- 对真伪、年代或价值产生误判

## Branch A2: 卖货客人——收购、议价或放弃

### Purpose

让玩家根据鉴定结果、卖家信息和当前资金，决定是否承担收购风险。

玩家主动结束调查，或卖家耐心耗尽进入最终报价阶段时，都会进入本分支。最终报价阶段关闭新的调查追问，但仍允许玩家报价、进行必要的最后议价或放弃收购。

### Player Action

- 接受卖家报价并收购
- 与卖家议价
- 继续询问
- 放弃收购

### Decision Factors

- 自己对真伪的判断
- 自己对年代和价值的估计
- 卖家报价
- 预计出售价格
- 当前资金
- 未来市场机会
- 持有成本
- 对方可信度

### Game Core Resolution

Game Core 检查资金和交易条件，并结算议价结果、收购价格、资金变化与库存变化。LLM 负责表现对话和谈判过程。

如果卖家已进入最终报价阶段，Game Core 还需要限制新的调查行为。玩家继续拖延、施压或指控时，Game Core 可以结算为卖家离店并使本次交易失败；LLM 只能表现该结果。

第一版中，玩家可以在资金不足时尝试压价，卖货 NPC 可以接受、拒绝或继续协商。如果最终成交价格仍然高于玩家当前资金，Game Core 不允许完成交易。

每名卖货 NPC 对本次交易拥有由 Game Core 保存的最低接受价格。玩家无法直接看到该价格；当报价低于最低接受价格时，NPC 通过对话拒绝成交或继续协商。

界面是否通过禁用交易按钮表现该限制，由后续 [[UX_FLOW]] 决定。

### Output State

如果收购成功，资金减少，古玩进入库存，并保存收购价格与玩家当时的鉴定记录。

如果卖货 NPC 不接受玩家能够承担的价格，或最终价格仍然超过玩家资金，本次交易无法完成，古玩不进入库存。是否产生额外关系影响仍待决定。

### Risk / Failure

玩家可能买入假货、买贵、占用资金，或因过度谨慎错过机会。

### Related Systems

- [[ANTIQUE_SYSTEM]]
- [[ECONOMY]]
- [[KNOWLEDGE_SYSTEM]]

## Branch B1: 买货客人——了解需求并推荐库存

### Purpose

让玩家理解买货客人的需求，并从库存中选择合适的物件进行推荐。

### Trigger

玩家通过对话发现客人希望购买古玩后进入本分支。

买货客人在到访前已经由 Game Core 确定购买目的，至少包含目标器物类别和可接受价格区间。买货客人不知道店内当前具体库存。

买家在初次交谈时只表达足以让玩家理解方向的宽泛需求，例如大致用途、器物类别或预算倾向。具体用途、品质要求、真实预算、预算弹性和购买急迫度，需要通过后续交谈、反应和报价逐步判断。买家不一定故意欺骗，也可能因为不懂、谨慎、试探或不愿暴露预算而表达不完整。

### Buyer Hidden State

买货客人的真实需求不能只表现为直接公开的类别和价格筛选。Game Core 应通过多个可组合维度表达其隐藏状态：

- **购买目的：** 收藏、自用、送礼、转卖、替他人寻找或其他合理目的。
- **专业程度：** 外行、略懂、熟悉特定器物，或具有较高行业经验。
- **预算弹性：** 接近固定上限、遇到合适物件可以提高，或故意压低公开预算。
- **购买急迫度：** 随便看看、近期需要，或急于成交。
- **谈判策略：** 直接询价、隐藏预算、压价，或试探玩家是否懂行与是否可信。

这些维度可以组合，不构成固定、互斥的买家类型。玩家需要通过交谈、买家对不同物件的反应、报价变化和自身关系经验逐步判断，而不是直接读取完整状态标签。

具体来客质量与隐藏状态的生成可能受到以下因素影响：

- 店铺声誉或信任度
- 店内商品质量
- 玩家当前经营状态
- 过去的交易记录
- NPC 关系
- 其他：

买货客人使用与卖货客人相同的底层交谈耐心框架，但耐心耗尽后的状态不同：卖家进入“最终报价阶段”，买家进入“最终选择阶段”。

在最终选择阶段，买家不再接受新的调查问题或新的库存推荐，但可以在已经看过的物件中作出最后决定、提出最后报价或离店。继续强行推荐、拖延或施压，可能使买家直接离店。

### Player Action

玩家可以：

- 询问客人的需求、偏好和预算
- 查看库存
- 根据客人的目标类别和价格区间推荐库存物件
- 查看系统依据买家公开的类别、约略价格和年代生成的库存匹配高亮或优先排序
- 在没有完全匹配物件时，从系统保留的弱匹配候选中选择是否推荐
- 推荐物件时准确说明其具体类别，并主动介绍物件适合客人需求的理由
- 与客人交流物件信息
- 选择不推荐物件

### Information Visible to Player

玩家可以看到系统依据买家已经公开的器物类别、约略价格和年代，对库存生成的匹配高亮或优先排序。该提示只表示物件与公开条件的匹配程度，不代表系统替玩家判断最值得出售、真伪最可靠或利润最高的物件；玩家仍需结合自己的鉴定记录与对话判断。

玩家选择推荐某件库存物件后，系统自动在物件介绍卡或对话起始信息中展示该物件的确定具体类别。这个类别展示不依赖玩家自由输入，也不能被 LLM 或推销话术覆盖；玩家可以在其后自由补充销售理由和物件特点。

如果库存中没有完全匹配的物件，界面应明确提示“没有完全匹配”，但仍保留符合部分条件的弱匹配候选，供玩家结合交谈、鉴定记录和经营判断决定是否推荐。玩家可以主动推销自己选择的弱匹配物件，但推荐时必须准确说明物件的具体类别；年代或价格偏差不要求玩家使用固定话术主动披露，玩家可以自行决定如何组织销售表达。系统不能把玩家的推销自动显示为完全匹配。完全不同大类或明显偏离公开需求的物件不属于第一版的常规推荐候选；这不等于允许玩家进行后续版本的主动推销玩法。

玩家重新查看所推荐物件的购入时鉴定记录。Game Core 在推荐时结合玩家当前知识、经验和已有线索重新计算该物件的判断和估值，并同时保留旧判断供玩家比较。客人的完整专业程度、预算弹性、购买急迫度和购买目的不直接显示，需要通过对话推断。

### Game Core Resolution

Game Core 根据客人的公开类别、年代要求和库存物件的对应属性，以及物件当前市场估值与客人公开的约略价格倾向，生成匹配高亮或优先排序。初次匹配不使用玩家的收购成本，也不使用玩家尚未提出的最终报价；当玩家主动提出报价后，Game Core 再生成报价与买家预算的模糊匹配反馈。之后再结合客人的隐藏兴趣、知识、购买能力和对推荐物件的判断，决定 NPC 是否感兴趣以及是否提出报价。匹配提示不能直接决定出售对象。

类别使用层级匹配：买家提出父类时，其子类物件可以进入匹配范围；买家提出更具体的子类时，精确子类优先，只有属于同一父类但不完全相同的物件才作为较弱匹配；完全不同的大类不匹配。

年代要求使用时间范围进行匹配：物件年代完全落在范围内时属于高匹配，部分接近或相邻时属于弱匹配，明显超出范围时属于低匹配。高亮和排序应表现这种模糊接近度，不应把年代匹配当成玩家已经确认的绝对年代。

如果没有同时满足公开类别、年代和价格条件的完全匹配，Game Core 不应把库存筛选结果清空，而应保留满足部分条件的弱匹配物件，并标记没有完全匹配的事实。玩家可以主动选择弱匹配物件进行介绍；买家是否接受、是否愿意议价以及是否因此失去兴趣，仍由其隐藏状态和 Game Core 结算。完全不同大类或明显偏离公开需求的物件不进入第一版常规推荐列表。

玩家可以通过准确介绍类别、主动推销、说明物件特点和谈判影响结果，但不能直接决定 NPC 购买，也不能把弱匹配说成完全匹配。玩家可以选择不主动强调年代或价格偏差；价格表达属于估值观点或谈判策略，本身不直接判定为说谎。对年代、来源、真伪等客观属性作出明确错误陈述时，是否构成误导或欺诈，按后续规则结算。

### Output State

这一阶段产生 NPC 报价、NPC 拒绝购买，或玩家没有可推荐的库存结果。如果没有完全匹配但玩家选择推荐弱匹配，仍可继续进入介绍和议价；如果没有任何可接受的匹配候选，或 NPC 不接受推荐，本次 Micro Loop 可以不成交并正常结束。

### Risk / Failure

玩家可能误判买家的真实预算、专业程度和购买目的，推荐不合适的物件或把弱匹配当成完全合适，过早接受低价、因报价过高失去交易，或因不恰当介绍损害信任。

### Feedback

LLM 根据 Game Core 确定的买家隐藏状态，通过买家的询问重点、措辞、对不同推荐的反应、报价与议价行为表现线索。反馈应允许玩家形成推断，但不能直接显示完整隐藏标签或保证玩家一定判断正确。

### Related Systems

- [[ECONOMY]]
- [[RELATIONSHIP_SYSTEM]]
- [[EVENT_SYSTEM]]
- [[UX_FLOW]]

## Branch B2: 买货客人——出售、议价或拒绝

### Purpose

让玩家根据当前判断、NPC 报价和长期信誉风险，决定是否完成出售。

### Player Action

- 接受报价并出售
- 尝试加价或议价
- 暂时不出售
- 拒绝交易
- 其他：

### Decision Factors

- 当前报价
- 收购价格
- 对物品真实价值的判断
- 可能获得的利润
- 客人的专业程度
- 交易对声誉和关系的影响
- 是否值得继续持有

### Game Core Resolution

Game Core 结算最终报价、谈判结果和交易是否成立，并保存物件真实状态、交易记录和后续流转所需状态。

系统不判断玩家是正常误判还是故意欺骗。只要售出物件真实为假，就可能在未来二次倒卖或被有能力的人看货时被发现。

### Output State

出售成功后，资金增加、物件从库存移除并生成交易记录。拒绝出售后，物件保留在库存中。

出售真实为假的物件会生成隐藏的待发现风险，但不会立即扣除信誉，也不会自动撤销已经完成的交易。

### Risk / Failure

- 玩家卖出真实为假的物件
- 假货在后续流转或看货时被发现，可能损害信誉和口碑
- 与相关 NPC 的信任或关系下降
- 触发影响后续客源、人脉或事件的结果

### Feedback

出售假货时不立即揭示真实答案。只有假货以后被真实发现，才进入 NPC 反馈、行业口碑、来客变化或事件影响判定；是否产生信誉损失及其程度由 Game Core 结算，并向玩家提供被发现的具体瑕疵作为学习反馈。

## Phase 4: 继续接待或结束当日营业

### Purpose

让玩家在一天内重复处理有限数量的客人，并在当日来客处理完毕后结束营业。

### Trigger and Timing

每次 Micro Loop 结束后，Game Core 检查当前营业阶段是否仍有尚未到访的客人：

- 如果仍有客人，自动触发下一名客人到访。
- 如果上午来客已经处理完毕，进入午间过场；玩家确认后开始下午营业。
- 如果下午来客已经处理完毕，进入晚上闭店与当日经营结算。

### Output

当日结算至少汇总玩家当前能够知道的资金、库存、知识、经验、关系和交易记录变化，并可根据事件条件呈现剧情余韵或下一营业日线索。尚未被真实发现的假货、错误陈述和隐藏后果不得在结算中提前揭示。经营成本的具体结算方式仍待设计。

### Risk / Failure

资金不足且没有可出售库存时，使用第 9 节定义的 V1 暂定经营恢复安全网。

## 5. Medium Loop：跨日经营与 NPC

多个章节化营业日构成 Medium Loop。V1 的主要玩法保持在店内，外部世界通过来客、器物、信件、电话、传闻、旧交易回访和爷爷留下的记录进入店铺。

NPC 可能：

- 成为熟客
- 提供知识
- 提供货源
- 提供市场信息
- 提供鉴宝工作
- 邀请玩家参加拍卖
- 邀请玩家参加交流活动
- 请求玩家帮助
- 将玩家介绍给新的 NPC

玩家与 NPC 的关系可能受到以下行为影响：

- 对话选择
- 是否接受帮助
- 是否完成委托
- 交易是否诚实
- 是否成功鉴宝
- 是否兑现承诺
- 是否在关键事件中帮助对方

外出拜访、拍卖、夜间场景和正式学习不属于 V1 Medium Loop，保留为后续版本候选。

## 8. Player Decision Model

本循环中，玩家必须进行哪些不可自动替代的判断？

- 玩家依据什么信息判断
- 玩家可以承担什么风险
- 玩家能否追加成本获取更多信息
- 玩家是否可能选择保守策略
- 玩家是否可能选择高风险高回报策略

## 9. Risk and Failure Model

主要风险包括：

- 买入假货或仿品
- 买贵
- 错过机会
- 信誉下降
- NPC 关系恶化
- 持有滞销古玩
- 资金不足
- 其他：

V1 暂定采用软失败恢复机制：当玩家资金不足以完成最低层级收购，同时没有可出售库存时，Game Core 在近期营业安排中保证出现一次基础鉴定委托。NPC 携带自己的物件并为玩家提供鉴定服务费，玩家无需先投入收购资金。

基础鉴定委托遵循以下边界：

- 完成委托即可获得一笔最低服务费，避免错误鉴定再次造成永久卡死。
- 鉴定质量可以影响额外报酬、知识、经验或口碑，但不取消最低服务费。
- 最低服务费只帮助玩家重新进入最低层级交易，不应高于正常经营的预期收益。
- 委托不能成为可重复刷取的无成本收入；章节化营业结构下应使用什么限制替代原定的时间或日程成本，仍待确定。
- Game Core 决定恢复条件、委托出现和资金结算；LLM 只负责表达委托与鉴定反馈。
- 该机制是 V1 暂定安全网，未来可以结合更现实的经营方式修改或扩展。

需要决定：

- 失败是否会导致 Game Over
- 是否存在软失败
- 玩家拒绝所有交易时循环如何继续
- 基础鉴定委托的触发阈值、出现时机与报酬范围

## 11. Game Core / LLM Boundary

### Game Core Decides

Game Core 必须决定：

- 资金余额
- 库存
- 古玩真实真伪
- 器物存在的可识别瑕疵及识别条件
- 真实年代
- 品相与核心价值
- 鉴定难度
- 玩家鉴定结果
- 数值化的真品可能性
- 允许向玩家表达的已发现线索与不确定性
- 随机结果
- 客人和 NPC 的核心状态
- 卖货客人的认知状态、表达诚实度、出售动机与谈判策略
- 卖货客人本次交互的耐心状态与提问消耗
- 买货客人的购买目的、专业程度、预算弹性、购买急迫度与谈判策略
- 买货客人本次交互的耐心状态、已看过的物件与最终选择阶段
- 客人在到访前已经确定的买货或卖货身份
- 每日来客数量与到访顺序
- 买货客人的目标类别与价格区间
- 卖货 NPC 的最低接受价格
- 交易是否成立
- 最终成交价格是否超过玩家资金
- 已售物件的交易与流转记录
- 假货是否在后续场景中被真实发现
- 假货发现后的信誉、口碑、关系和学习结果
- 奖励与惩罚
- 事件条件是否满足
- 世界状态变化

### LLM May Express

LLM 可以负责：

- NPC 对话
- 卖家说法
- 客人语气
- 客人通过对话表达的购买或出售来意
- 谈判措辞
- 古玩描述
- 鉴定反馈的叙事表达
- 严格依据 Game Core 授权信息生成的玩家内心独白
- 事件候选文本
- 记忆摘要
- 根据授权状态生成合理反应
- 根据卖货客人的隐藏状态生成一致但不直接泄露标签的说法、隐瞒、试探和谈判表现
- 根据 Game Core 提供的耐心状态表达逐渐变化的态度与拒答反应

### Boundary Rule

```text
LLM Output
→ Parser / Validator
→ Game Core Rule Check
→ Game Core State Update
```

LLM 可以提出候选行为、候选事件或表达方式，但不能直接修改权威游戏状态。

## Scenario D：已售假货在二次转卖时被懂行买家发现

这是 V1 的标准“客观错误后续发现”范例，用于验证交易风险、发现者能力和长期后果之间的关系。它不是每次售出假货后必然发生的固定事件模板。

### Initial State

- 玩家已经通过收购获得一件真实为假的瓷器。
- 该物件的基础类别为瓷器，具体类别字段确定；真伪存在隐藏真实状态。
- 假货问题并非当前玩家经验能够稳定识别的明显问题。
- 玩家在购入时获得概率式鉴定结果，并未得到“判定为假”。具体概率为示例数据，不代表已经锁定的数值。
- 玩家之后将该物件卖给一名普通买家，交易完成并钱货两清。
- 交易记录保存物件真实状态、交易双方、成交价格和玩家当时的鉴定/表达记录。

### Later Trigger

普通买家准备再次转卖该物件，并请一名懂行买家或相关 NPC 看货。Game Core 根据发现者能力、物件问题的明显程度、当前可观察线索和具体情境，判定是否真实发现问题。

### Possible Result

- 如果未发现问题：物件继续流转，玩家暂时不会收到信誉处罚，后续仍可能再次触发发现机会。
- 如果发现问题：Game Core 将该客观错误标记为已发现，并进入后续影响判定；不保证每次发现都会产生信誉或口碑扣除。
- 后果是否发酵以及发酵程度，由 Game Core 根据问题严重程度、假货成交价格、买家身份、交易关系和传播范围决定。问题严重程度只描述问题本身对物件真实价值与行业判断的影响，分为三档：轻微问题是局部瑕疵或有限价值偏差；严重问题是真伪、年代、来源等重大错误，明显改变价值判断；极严重问题是关键属性完全虚构，或物件本质与玩家陈述严重不符。同一物件存在多个问题时，取最高严重程度作为主问题等级，其余问题作为附加影响因素保留；每个问题仍需独立记录和判定是否被当前发现者识别，一次事件只反馈被识别的问题，未被识别的问题继续保留为隐藏风险。本次影响判定只使用本次实际被识别的问题，不提前按隐藏问题的真实严重程度产生后果。同一个问题的基础后果只结算一次；后续发现只有在进入新的传播圈层、涉及新的关系对象或满足新的事件条件时，才可能产生新增影响。传播范围暂分为个人关系圈、行业圈、公众/市场圈。个人关系圈进入行业圈需要买家向同行咨询、再次转卖时请懂行者看货或进入正式鉴定；行业圈进入公众/市场圈需要形成公开争议、重要人物介入或事件被公开传播。没有满足明确触发条件时，问题停留在当前圈层。玩家可以尝试联系买家解释、请求暂缓转卖、提供补充信息或利用已有关系进行有限干预；每个传播圈层阶段最多进行一次主要干预，具体代价由事件规则决定，V1 不再预设为时间或日程成本。干预不自动撤销交易，也不保证阻止传播，是否成功由 Game Core 根据关系状态、玩家提供的信息和事件条件结算。成交价格只参与真实发现后的影响判定，不参与问题分档或发现判定。V1 的买家身份暂分为普通买家、懂行买家或行业相关 NPC、有行业影响力的买家，分别对应较小、中等和较大的传播与发酵潜力，但不代表必然产生后果。发现者层级只影响此次检查能否识别问题，不直接决定处罚强度，也不等同于买家身份层级。
- 原始交易不退款、不撤销；玩家不能通过该事件自动取回物件或退还成交款。
- 玩家获得与被发现问题相关的可验证信息、知识或经验收益，具体收益尚未锁定。

### Player Feedback

玩家不会在原始交易完成时被提前告知物件一定是假。问题被真实发现后，系统通过相关 NPC 的检查结果、对话反馈或事件表现告知玩家被发现的客观问题；LLM 负责表现过程，Game Core 决定发现事实和状态变化。

### Design Questions Illustrated

- 普通买家为什么没有发现，懂行买家为什么可能发现？
- 发现者需要看到什么线索才能触发发现？
- 发现后是否发酵、先作用于哪一层，以及假货成交价格如何改变三档买家身份带来的影响：相关 NPC 信任、店铺信誉、行业口碑还是后续事件？
- 玩家获得的学习反馈如何帮助下一次鉴定，而不直接保证以后永远正确？

### Blocking

- 当前无阻止 Core Loop 继续设计的恢复机制问题；V1 已有暂定安全网。

### Important

- 哪些瑕疵足以让玩家直接判定为假，识别它们分别需要什么经验？
- 假货或其他客观属性错误在后续场景中的具体发现条件是什么？
- 假货被发现后，三档问题严重程度、三档买家身份、成交价格和交易关系如何共同决定无影响、轻度或重度发酵？三档问题的具体边界和成交价格参与影响判定的区间、权重是什么？
- 发现者层级只影响发现结果，还是在特殊事件中也会影响传播范围？
- 玩家能否主动花钱获取更多信息？
- 客人的专业程度是否直接显示？
- 玩家拒绝交易是否消耗时间或影响关系？
- 交易结果如何影响声誉和 NPC 关系？
- 知识与经验在循环中分别影响什么？
- 经营成本的结算时机是什么？
- 滞销物品是否存在持有成本或机会成本？
- 店铺名声、对外商品口碑、公开展示和历史成交表现如何影响每日来客数量、身份与质量？
- 连续同类客人的具体上限是多少？
- 基础鉴定委托在何种资金与库存阈值下触发、多久内出现、最低服务费是多少？
