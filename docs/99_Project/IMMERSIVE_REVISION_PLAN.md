# 第二轮试玩改版：场景、交谈与调查

## 当前阶段

用户六项答复已收到，按DEC-070进入实施：双侧对话卡；4家老店＋每日3～5随机摊、各5～8件货；夜间茶馆和条件拜访；聊天议价＋明确成交确认；可跳过序章及疑问笔记；本机受保护保存Key，开发真实模型联调累计人民币10元上限。价格未知或未保存可用配置时不调用。

用户随后确认第二轮界面结构改进：场景热点与悬停提示、对白区折叠、会面摘要与历史开关、透明人物/器物素材、整数报价、经营与剧情笔记分栏，以及所有剧情相关 NPC 的情境提问入口。该轮仍属于原型实现，不改变正式锁定规则。

## 实际缺口

- chapter_main的_append_system、_append_inner与人物对白共用_append_line，没有独立的信息层。
- conversation_history在每次来客重置；模型取最近8条文字，长期记忆主要是交易与剧情选项摘要。不存在足够的跨会面已谈话题、承诺、物件指代和未答问题记录。
- answer_suggestions每次主要返回来源、线索、未知三套句式，不随买家实际问题选择响应内容。
- 市场实际上是两件固定外部物件的轮换入口，不是多个经营主体、完整库存或真实场景流转。
- 夜晚仅闭店及资料/外出面板，没有独立的夜间人物交谈场景。
- 章节虽有旗标和分支，却缺少正式序章、可翻阅信件/照片和持续可见的调查问题板。

## 用户已经明确的方向

保持Godot和第一章基础。本轮不是扩写更多营业天数，而是把现有经营、人物与故事做成可体验的场景。

1. 人物对话独立显示；系统结算、私人鉴定和资料不再混入双方聊天。
2. 本机保存API接入配置与Key；普通存档只引用配置，不夹带凭据。提供显示脱敏、删除和禁用自动联调的入口。
3. 人物具备同场、跨场与跨日连续记忆；事实卡可查，不再让模板替玩家机械复述。
4. 市场总览 → 商户/摊位预览 → 独立店内库存 → 选物验货与交流 → 返回市场或自家店铺。
5. 齿轮、货架、门、账本、笔记承担不同入口；可发现的热点有悬停提示与键盘替代，不让“去掉按钮”变成找不到操作。
6. 序章通过信件/照片/场景文字建立返乡接店的处境；调查板分开“已知事实、我的疑问、可走访方向”，不泄露隐藏答案。
7. 每个剧情相关 NPC 都由同一份故事数据提供可选情境问题和快捷按钮；按钮只授权一次有边界的提问，不直接解决剧情节点，玩家仍可自由输入。

## 建议实现顺序

1. 先完成对话与信息分层，以及API本机安全保存；为真实模型测试建立可控入口。
2. 重构对话上下文：结构化当前会面、逐人物可见记忆、当前物件、未答问题、已公开事实与原话索引；模型只表达，不成为事实存储。
3. 建立共享场景导航与可恢复交互状态，再做市场、商户、夜间交流，避免每个地点重复造一个弹窗系统。
4. 接入序章资料、任务式疑问板、条件线索和夜间角色回访。
5. 用实际接入模型做费用受限的多轮回归与视觉试玩；保留本地故障模拟，不能再用它替代对白质量验收。

## 集中选择（已完成，见DEC-070）

- 对话视觉：双侧人物消息，或单句视觉小说表现。
- 市场范围：固定老店/随机摊位数量及每家货量。
- 夜间：固定茶馆，或茶馆与条件拜访共同构成夜间场景。
- 谈判：自由交谈识别意图，机械成交是否保留明确确认。
- 故事引导：开场资料与调查方向提示的强度。
- 真实模型联调费用上限已确认累计人民币10元；禁止在聊天中提供Key。本机已保存受保护配置并完成受限连接验证。

## 实施进展

2026-09-06追加试玩修复：流程按钮脱离对话容器；场景轮廓按背景图坐标绘制；市场改成4家固定店/每日3～5摊的场景入口与悬停介绍；商户使用大面积三列网格，详情顶部提供鉴定与整数报价，交割经Core确认。商户兼营少量非主营类别。设置支持命名的受保护配置切换及Kimi Code可编辑模板。具体参数仍为原型，不锁定生产规则。

本轮验收要求：真正可见的流程按钮走通十日；场景轮廓与可点击区域一致；市场入口数量与当天商户一致；详情鉴定后可以还价购买且只结算一次；当天库存不因重入刷新；切换模型不得串用Key或影响进行中的回复；桌面渲染截图复核。

2026-09-07追加第二轮试玩修复方向：店内场景采用明确的背景、热点、人物/器物、UI分层；对白展开时隐藏场景热点，避免轮廓穿过前景，收起时恢复可点击区域。私人判断归入右侧信息栏，不覆盖外部场景商品。商户物件统一使用“查看物品”入口；会面资料默认折叠，快捷问题放入有限高度滚动区。玩家在商户交谈中同时提到多个商品时必须先明确目标物件。剧情人物的夜间正事继续使用点击选项，非剧情拜访改为一次性对白，输入框只作为闲聊/回顾入口。具体的剧情节点、地点美术和模型长期一致性不在本次修复中锁定。

场景原型已接入默认启动入口，本地规则与界面验证见 [[IMMERSIVE_REVISION_ACCEPTANCE]]。市场双列商户卡、独立夜景、对白分层、可恢复会面、序章资料、本机配置保存和本轮信息分层已可试玩。实际模型的连续对白质量仍待验收，不能用模拟回复替代。新版透明素材图集已接入，棋盘格清理脚本保留在 `prototype/tools/flatten_checkerboard.py` 供资产更新复用。

## 验收条件（不是代码编译即可通过）

- 一段双方交谈中不出现系统日志或未出口内心；不同人物可视觉辨认，资料仍容易找到。
- 客人已听到的来历、已问过的问题、被回应的疑问与已达成承诺，在切场景/读档后仍一致；未告知的鉴定不能成为其记忆。
- 客人问品相时建议回答品相，问来源时回答来源，缺证据时自然承认未知；不把建议直接当成玩家已说出口的话。
- API重启后可恢复配置；仓库、普通存档和日志不含Key；忘记凭据可执行；调用受预算保护。
- 市场里存在多个可辨经营主体和多件可购买物件；重复进出不复制物件、不重置议价、不刷新品；随机刷新条件由Core决定。
- 夜间能真正与NPC交流和查验已授权物件，而不只是显示一条说明；所有外部场景均有清楚的返回路径。
- 开场让玩家说得清“我为什么在这里、先经营什么、爷爷留下什么疑问”；调查板随实际线索更新，不伪造任务完成。
- 保留已有资金、物权、隐私、知识、耐心和重试不重结算的测试，并补充这轮真实体验验收证据。
- 场景中的热点能被发现、悬停解释并可用键盘触发；对白可收起，摘要/历史/私人判断不混入人物对白；所有剧情相关 NPC 都有数据驱动的情境问题入口。
