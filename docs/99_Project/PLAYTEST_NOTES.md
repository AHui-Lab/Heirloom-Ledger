## 2026-09-06：新版沉浸式界面第二轮反馈与确认

来源：用户实际试玩后的十项界面/信息结构反馈，以及后续集中确认。

本轮问题归类：

- UX：场景热点、书本和门的交互不够可发现；需要鼠标附近悬停提示，并保留键盘可操作性。
- UX：对白面板占据过多空间，需要可收起/展开；历史记录需要独立开关，且当前会面应有摘要。
- UX / Presentation：人物与器物素材带有矩形背景；需要透明或可自然融入场景的素材处理。
- UX / Information Architecture：人物资料、系统记录、私人鉴定、故事和交易信息需要明确分层，避免同一屏幕中互相混淆。
- UX / Interaction：报价必须支持精确整数；故事笔记需要说明“当前发生了什么、下一步能做什么”，而不是只列标题。
- Story / UX：每个与剧情有关的 NPC 都应有剧情情境提示和快捷提问按钮，不只为许闻溪提供特例；快捷提问不能替玩家自动作出剧情选择。

已确认的实现方向：场景热点覆盖实际货架、门、账本、笔记和柜台物件；悬停显示邻近提示；对白区可折叠；会面摘要、历史开关和交易状态独立显示；人物/器物素材使用透明化处理后的图集；笔记分为经营、剧情、人物、器物四类；故事提示由数据驱动，统一覆盖所有剧情相关人物；钱货交割仍需明确确认。

本轮实现与验证见 [[IMMERSIVE_REVISION_PLAN]] 和 [[IMMERSIVE_REVISION_ACCEPTANCE]]。这些是当前沉浸式原型的确认方向，不自动升级为正式 locked 规则。
## 2026-09-07：第二轮试玩后的场景与对话体验反馈

来源：用户两次实际试玩及八张场景截图。本条记录的是体验问题和改版方向，不自动改变正式 locked 规则。

- 场景层级：货架、门、账本和台面热点的高亮轮廓曾压到人物、账本和器物；对白展开时应只保留人物、当前物件和背景，收起后再恢复场景交互。
- 外出导航：纯文字地址按钮缺少地点感；应使用融入场景的图像卡片，保留简短地点名和用途说明。
- 市场总览：建筑轮廓存在误圈和重叠；市场总览只保留店招/摊位招牌作为可点击入口，建筑区域仅作为命中范围。
- 商户物件：物件详情入口应叫“查看物品”，私人判断不能藏在商品网格后面；判断应放在信息栏或当前物件详情中。
- 物件指代：玩家一句话同时提及多个商品时，系统不能擅自选择其中一件；必须先要求玩家明确当前交谈物件。
- 新手引导：卖货、买货和剧情交谈都需要更明显的可直接点击问题；自由输入保留，但不能要求没有专业知识的玩家凭空知道该问什么。
- 夜间结构：听雨茶馆只承载当晚在场的特殊人物或事件；不在茶馆且没有剧情的人只进行一次简短拜访对白；剧情人物使用点击式选择推进，闲聊和交易回顾才使用自由模型对话。
- 状态残留：从夜间或外部场景把物件拿给 NPC 后回店，不应自动把该物件重新放到柜台；返回店铺时清理临时展示选择。
- 信息密度：会面资料、快捷问题和历史开关曾挤压实际对白；会面资料默认收起，快捷问题限制在独立滚动区。
- 物件判断索引：取消按日期排列的“器物与判断”总时间线，改为从每件物品详情查看其当前判断与历史。

本轮实现先处理确定的 UI 和交互缺陷；剧情内容的吸引力、故事节点对白和真实模型的长期一致性仍需单独试玩评估。
