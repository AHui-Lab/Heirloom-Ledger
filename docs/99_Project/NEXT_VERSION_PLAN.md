# 新版可玩版本规划

本文件记录本轮试玩反馈、新版交付与验收边界。内容规模、美术和剧情方向已由六项答复确认，见DEC-069；不是永久locked设计。完整目标包括对话修复、模型稳定性、辅助提示、场景与人物、扩大的经营玩法、可信剧情与跨日NPC推进。

## 当前证据

- 当前原型是 Godot 单营业日、四名固定客人、三件初始库存，尚无跨日剧情与存档。
- 三张入店截图显示：NPC 标签下生成掌柜的迎客话。提示词没有为开场明确交谈双方与句子归属，叙事事件被包装为“玩家本次表达”；存在角色错位风险。
- 观察动作在 Game Core 中明确要求“以客人的身份回应玩家的观察”，使玩家观察结论被 NPC 说出来。鉴定才使用内心独白路由。
- 报价截图显示一次失败后重试成功；未显示当时完整 HTTP 或网络错误，不能据此认定 Key 无效。
- 本地 Godot 历史日志仍有 main.gd:844 的 void 异常，回溯来自 llm_client.gd:156 的“无可显示文本”分支。void 异常已在前次修改中处理，但底层空正文原因未被记录。
- 普通请求 Token 上限被 min(220, 用户配置) 截断，测试上限为 60；调高 UI 参数实际无法提高预算。推理预算耗尽是待验证假设，不能视为已证实根因。
- 请求没有结构化诊断日志；需记录状态、耗时、finish_reason/status/incomplete_details、用量、重试次数，不保存 Key 或 Authorization。
- 库存已有 provenance 字段，但没有针对客人问题的资料入口与玩家回答选项；买家交谈的 source 行为错误转向询问买家用途。
- 额外发现：售假成功的 system_text/day_notes 立即提示“真实问题尚未被外界发现”，泄露隐藏真相，与现有发现后果规则冲突。
- DESIGN_PHASE_STATUS 仍写 Programming: Not Started、Engine: Undecided。需要区分设计成熟度与探索原型实际进展。

## 已确认交付规模

2026-09-05 用户六项答复已收到，现按 DEC-069 执行：完整第一章约10个营业日、8名重要NPC、至少24件器物、有分支收束；中式写实插画且允许AI生成；行业人情与家族旧事；加入外出、拍卖；事实卡加2～3条可编辑回答；暂不付费联调。以下原提案的待确认内容以本段为准。

已制作第一章《旧账未清》：10个章节化营业日、8名重复来访的重要NPC、28件器物数据（含4件初始物件及4件店外物件）、3类章节收束。事件按日期与证据条件出现，可以搁置继续经营。具体证据和限制见CHAPTER_ONE_ACCEPTANCE。

继续采用Godot，上午、午间、下午、闭店，无行动点、无精确时钟；本章每日4位常规客人。用户已重开店外活动：古玩街、专家拜访和小型拍卖作为本轮原型范围。

## 实施顺序与交付物

1. 稳定性：明确 NPC / 掌柜 / 内心 / 旁白四类说话人，拆分开场事件和玩家发言；修复预算、协议兼容、诊断及重试。交易结算与对白重试分开，重试不重复扣钱、给知识或消耗耐心。
2. 内容规格：编写第一章剧情、角色动机与记忆、器物档案、发现事件、知识提示及来源引用。将正式已确认规则与原型调参区分；新重大规则记录待决项。
3. 数据与经营：将内容从 Game Core 拆到数据文件；实现跨日库存/账本、分领域知识经验、概率与明确判假、需求匹配、议价、推荐说明、耐心与一次挽回、三类社会评价、后续发现及传播干预、恢复委托。
4. 剧情与人物：实现旧账本、器物线索、旧交易回访、承诺与关系记忆、条件事件、分支收束。NPC 只能知道亲历、告知或已传播的事实。
5. 视觉与交互：统一风格店铺场景、柜台人物、物件插画；点击柜台/货架/账本/笔记进入对应界面。加入入店、摆物、查看、成交反馈与轻量声音；人物表情或姿态随已授权态度变化。
6. 玩家帮助：客人问来历/工艺时出现“查看这件物品资料”和有事实依据的候选回答；明确区分记录、卖家说法、当前判断、未知。允许如实说明不确定；提示不泄露后台真伪、预算或标准答案。
7. 验收：保存/载入、章节完整游玩、两条经营路线、破产恢复、重复请求/超时/空正文/断网、隐藏状态防泄露、多窗口尺寸实际渲染。有效模型联调须使用用户允许的配置与调用额度，不以无效 Key 的 401 测试替代真实生成验收。

## 剧情方向（已采用的原型方案）

现实底色的返乡经营故事《旧账未清》（工作名）：玩家整理爷爷留下的无价格账目，遇见与同一批旧物相关、记忆和利益不同的来客。器物牵出的是保管、交易与承诺的纠葛；玩家需要比较流传记录、物件特征和各人的说法，决定如何经营与承担过去的关系。爷爷也可以有误判与难处。每次关键发现要有可追溯证据和经营选择，不能只点下一段对话。

保留 X City 为虚构城市。现实资料用于器物知识和行业生活质感；人物和情节原创，不把虚构案件伪称真实史事。

## 完成条件

用户确认后的规模、玩法清单与边界全部进入逐项验收表；每项必须有代码/内容、相应测试或实际游玩证据。原型参数和剩余风险单列。正常结算不泄露隐藏状态，开发者复盘另设明确入口。仅有编译通过、截图漂亮或通用网络测试通过，均不足以认定新版完成。
