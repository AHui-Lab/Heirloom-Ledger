# World State
World State 是 Game Core 管理的权威游戏状态，至少需要能够表达玩家资金、库存、知识、经验、关系、事件条件、成就及世界中的 NPC/机会状态。

World State 需要记录当前营业日、当前流程阶段（上午营业、午间过场、下午营业或晚上结算）、上午与下午的来客安排、当前客人、尚未出场的来客队列，以及当日已经完成的交易与事件。V1 不需要记录连续时间、精确钟点、交易耗时、活动时间成本、预约冲突或可中断活动进度。

每名来客除买货或卖货身份外，还可以具有常规经营、判断挑战、剧情锚点、后果回访或经营恢复等由 Game Core 决定的内容职责。剧情触发记录必须来自预先编排的节点或明确事件条件，不得因当天尚无剧情就由 LLM 自动补充权威事件。

判断挑战职责及其具体来源属于隐藏状态。对于每项判断挑战，World State 至少需要保存：挑战来源、玩家可能发现的有效线索、线索的可见或授权条件、能够利用线索的相关玩家行为，以及可能产生差异的结果分支。挑战可以与买货或卖货身份及其他内容职责重叠。除教学日或明确的经营恢复日外，Game Core 在确认标准营业日队列前必须验证其中至少有 1 名有效的判断挑战客人；教学或恢复例外也必须保存明确来源。

普通标准营业日的判断挑战数量必须为 1～2 名；教学日和明确的经营恢复日可以为 0 名。重要剧情日最多允许 3 名，但队列需要保存剧情例外标记及来源。Game Core 还应验证判断挑战没有覆盖当天全部来客，并在生成失败时调整案件组合。

“有效线索”表示玩家在满足相应知识、经验、观察或提问条件时有机会获得用于判断的信息，不表示必然揭示全部真相或保证正确选择。若案件没有任何可获得的相关依据，或所有结果均不受玩家判断影响，就不能计为判断挑战。LLM 生成的措辞、语气或临场矛盾不能反向写入挑战来源和权威线索。

World State 需要保存当天由 Game Core 选择的经营主题、主题来源、允许影响的候选内容范围，以及实际应用到来客或案件生成中的结果。主题只能在生成前调整权重；来客、器物和 NPC 隐藏状态一旦确定，主题不得被用来事后改写其权威事实。纯经营日必须具有一个经营主题，剧情日是否附带主题由内容规则决定。

主题来源需要区分世界驱动与玩家驱动，并记录玩家驱动所依据的信息是否已经公开或传播。公开陈列、历史成交、类别口碑、NPC 关系和已传播事件可以成为来源；隐藏库存、未发现问题及未传播事实不得进入外界来客生成条件。主题可以组合多个有效来源，但同一来源的重复影响与权重叠加上限尚未确定。

World State 还需要保存普通公开交易累积的对外信号、对应类别或价格层级、当前累计程度、是否达到主题资格门槛，以及信号来源与最近更新时间。重要 NPC 公开成交、高价值公开交易和重大传播事件可以创建立即具备候选资格的信号。主题资格只作用于尚未生成的营业日；当天来客安排生成后，本日新增信号不得回写或重排本日队列。具体门槛、衰减和高价值相对标准尚未确定。

类别口碑需要按器物类别记录精确内部值及当前玩家可见阶段。V1 的可见阶段固定为：尚无名气、偶有人提起、逐渐形成口碑、在相关圈子里受到认可。内部值、档位阈值和距离下一档的进度均属于隐藏状态；只有 Game Core 可以计算和改变，UI 与 LLM 只接收当前阶段及获授权的变化原因。

World State 必须将类别口碑、全局信誉和 NPC 关系保存为三个独立字段或状态集合，不得合并为统一声望值。类别口碑按器物类别索引，全局信誉属于店铺整体状态，NPC 关系按具体 NPC 索引。事件结算需要分别记录每项变化的目标、原因、传播圈层和已结算状态，避免一项影响被重复映射到其他维度。具体 schema 与数值范围尚未确定。

全局信誉需要记录精确内部值及当前玩家可见阶段。V1 的可见阶段固定为：声誉受损、尚无定论、口碑稳定、值得信赖。内部值、阶段阈值和距离下一档的进度属于隐藏状态；UI 与 LLM 只接收当前阶段、变化方向及 Game Core 授权公开的原因。

每名重要 NPC 的关系状态需要记录精确内部值及当前玩家可见阶段。V1 统一使用防备、生疏、熟悉、信任、深交五档。内部值、阈值和距离下一档的进度属于隐藏状态。NPC 的重要记忆、承诺、冲突、利益条件和社会连接必须与关系值分开保存，并在 Game Core 判定人物行为时共同参与条件检查。

标准营业日的上午与下午各安排 2～3 名客人。4 名时保存为 2/2，5 名时由 Game Core 根据买卖组合、剧情、经营主题和节奏选择 2/3 或 3/2，6 名时保存为 3/3。买货与卖货身份只在全日满足各约 2～3 名，不要求每阶段固定类型。等待队列中的具体人数、身份、来意、需求和顺序属于 Game Core 权威状态，当前交互期间只向玩家暴露“是否仍有客人等待”。当前阶段来客全部处理后，Game Core 才能进入午间过场或晚上结算。突破人数范围必须具有明确的重要剧情例外标记。

全日队列还需要保存并校验连续同类客人数。普通队列中连续买家或连续卖家不得超过 2 名，上午与下午边界不重置计数。允许连续 3 名同类客人的队列必须保存对应的剧情或经营主题例外标记及来源；没有有效标记时，Game Core 应在营业日生成阶段调整顺序，而不是交给 LLM 修正。

当前客人交互需要支持“正在显示”和“暂时切出但仍保持”两种界面状态。暂时切出时，World State 保留当前客人、对话历史、已公开信息、交谈耐心、交易阶段和未完成选择；界面导航本身不触发耐心或 NPC 行为变化。等待队列仍与当前交互分离，不能因展示当前客人的返回入口而公开其他等待客人的身份。

当存在未结束的当前客人交互时，Game Core 只允许信息查看类导航和本次交易必要操作。库存与筛选、账本、历史交易、人物已公开资料和已有鉴定记录可以打开；本次交易相关的观察、鉴定和物件选择继续写回当前交易状态。V1 不在此状态下启动店外活动或独立耗时活动。

卖货客人的权威交易状态需要能够分别表达其对物件的认知、表达诚实度、出售动机和谈判策略，而不是保存单一、互斥的卖家类型或仅使用一个“是否说谎”标签。这些状态可以组合，并由 Game Core 决定；LLM 只接收表达当前对话所需的授权信息。

买货客人的权威交易状态需要能够分别表达购买目的、专业程度、预算弹性、购买急迫度和谈判策略，而不是只保存公开类别与价格区间。上述状态可以组合，由 Game Core 决定；玩家只能通过对话与行为反馈逐步推断。

买家状态还需要区分初次可公开表达的宽泛需求与暂时隐藏的具体用途、品质要求、真实预算、预算弹性和急迫度。哪些信息在每次对话行动后获得授权，由 Game Core 根据状态、玩家行为和规则决定。

买家状态还需要保存当前已公开的器物类别、约略价格和年代要求。Game Core 可以结合这些条件、物件属性和当前市场估值为库存生成匹配结果或优先顺序；初次匹配不使用玩家收购价或尚未提出的最终报价。玩家提出报价后，Game Core 可以另行生成报价与预算的模糊匹配反馈。该结果是对公开条件的机械整理，不应直接替代玩家的推荐决策。

库存匹配状态还需要能够表达是否存在完全匹配，以及在没有完全匹配时保留的弱匹配候选。弱匹配不会自动变成玩家必须推荐的物件；玩家可以主动选择并推销，买家是否接受仍由 Game Core 根据隐藏需求、预算、耐心和对话反应结算。完全不同大类或明显偏离公开需求的物件不进入第一版常规推荐候选。

推荐或推销库存物件时，交互状态还需要保留该物件的权威具体类别和其相对买家公开需求的匹配偏差。玩家可以主动推销弱匹配，但对话表达不能改变类别字段或把弱匹配写入完全匹配；年代或价格偏差是否被主动披露不作为推荐成立的前置条件。实际推荐结果和买家接受结果仍由 Game Core 结算。

推荐动作还需要触发由 Game Core/UI 提供的类别事实展示，确保买家交互上下文中出现物件的确定具体类别。该展示不由 LLM 自行生成或决定是否出现，玩家后续的自由推销只能补充表达。

World State 还应区分 Game Core 的市场估值、玩家的销售观点或报价，以及物件的客观属性。玩家报价或价格判断不因与市场估值不同就自动成为错误事实；年代、来源、真伪等客观属性的明确错误陈述，才需要进入后续误导或欺诈判定。

为支持后续发现，World State 还需要保存玩家对年代、来源、真伪等客观属性作出的相关陈述及其发生时点。交易完成时不立即根据该陈述处罚或揭示真相；只有在后续场景中由 Game Core 判定相关错误被真实发现时，才触发相应后果。第一版不要求在交易当下确定玩家是误判还是故意欺骗。

年代要求应保存为时间范围或等价的模糊区间，匹配结果至少能够区分完全匹配、部分接近和明显超出。匹配使用物件当前可用的年代信息，不应将高匹配结果写入玩家已确认的鉴定事实。

物件类别是物件的确定基础属性，World State 应支持其父类与子类关系。Game Core 根据买家要求的类别层级与物件当前类别生成精确匹配、同父类弱匹配或不匹配；真伪、年代、品相和价值的不确定性不应改变物件的基础类别字段。

单次交易对话还需要保存由 Game Core 管理的精确交谈耐心或等价阈值，以及已经发生的有效对话行为、已询问主题和相关结果。精确值不直接向玩家显示；系统仅提供模糊阶段与 NPC 态度反馈。耐心按验证后的语义行为而不是原始消息条数结算。LLM 可以接收表达态度所需的耐心阶段，但不能直接扣除、恢复或判定该状态耗尽。

状态还需要记录本次交互是否已经使用过耐心挽回机会。道歉、解释或主动退让只能触发一次候选挽回；Game Core 根据 NPC 性格、关系和受冒犯程度决定是否恢复少量耐心，且不得超过本次交互的初始上限。

卖货交互还需要保存当前是否已经进入最终报价阶段。进入该阶段后，Game Core 禁止继续获取新的调查信息，但仍可接受报价、必要的最后议价或放弃操作；继续拖延是否导致 NPC 离店由 Game Core 结算。

买货交互同样需要保存当前是否已经进入最终选择阶段。进入该阶段后，Game Core 禁止新的调查问题或库存推荐，但仍可处理已看过物件的最后决定、最后报价或离店结果。

- 为支持钱货两清后的客观错误发现事件，World State 还需要能够追踪已售物件的交易与流转状态、尚未暴露的假货风险、可识别瑕疵、玩家相关客观属性陈述，以及后续发现者的能力层级。问题严重程度暂分为轻微、严重、极严重三档；同一物件存在多个问题时，最高严重程度作为主问题等级，其余问题作为附加影响因素保留。每个问题需要独立保存发现状态；一次事件只更新被当前发现者识别的问题，未被识别的问题继续保持隐藏风险，本次影响判定也只使用本次已识别的问题。每个问题还需要保存发现历史、已结算的基础后果、已受影响的关系对象或传播圈层，避免同一个问题重复结算同一基础影响。每个传播圈层阶段还需要保存是否已经使用主要干预、干预结果以及所付出的事件代价。传播范围暂分为个人关系圈、行业圈、公众/市场圈；个人关系圈进入行业圈的触发包括买家向同行咨询、再次转卖时请懂行者看货或进入正式鉴定，行业圈进入公众/市场圈的触发包括形成公开争议、重要人物介入或事件被公开传播；Game Core 决定是否满足触发条件、是否进入更大的圈层以及是否产生新增影响。发现者暂分为普通客人、懂行买家或相关 NPC、专业鉴定人三个层级。实际能否发现由 Game Core 结合问题明显程度和情境结算。成交价格不参与发现判定，只在真实发现后参与影响判定。发现者层级不直接决定后果强度，也不保证发现后必然产生处罚。原买家身份暂分为普通买家、懂行买家或行业相关 NPC、有行业影响力的买家，Game Core 还需要依据问题严重程度、假货成交价格、买家身份、交易关系和传播范围判定是否发酵及其程度。具体 schema 尚未确定。

玩家鉴定记录还需要能够保存 Game Core 生成的数值化真品可能性、玩家已发现的线索、当时的能力状态和鉴定发生的上下文。购入时及之后各次鉴定记录都需要保留，不能被新结果覆盖。LLM 生成的内心独白不是权威状态，可以依据对应记录的授权数据重新生成。

示例（仅为边界示意，不是当前数据结构）：
```yaml
item_id: item_0001
category: porcelain
actual_period: late_qing
claimed_period: kangxi
authenticity: imitation
base_market_value: 3200
seller_expectation: 1800
identification_difficulty: 72
```

上述真实字段不应直接暴露给玩家或由 LLM 改写。具体 schema、持久化方式和事件状态机待定。
