# LLM Design
核心原则：**Game Core decides reality. LLM interprets and expresses reality.**

V1 不模拟连续游戏时间。上午营业、午间过场、下午营业和晚上结算由 Game Core 按章节化流程推进；LLM 生成耗时、玩家现实阅读时间、界面停留时间和对话消息数量都不能推进阶段、安排客人到访或改变 NPC 状态。NPC 耐心只依据经过校验的语义行为变化。

LLM 可负责 NPC 对话与反应、动态事件表现、随机事件候选、行为意图、客人语言、古玩背景描述、报价与谈判语言、故事文本、记忆摘要，以及依据当前 World State 生成合理表达。

LLM 不拥有资金、库存、真实真伪、内部年代、核心市场价值、最终随机结果、胜负、任务条件或物品拥有权的最终决定权。所有权威事实由 Game Core 提供并校验。

买货客人的购买目的、专业程度、预算弹性、购买急迫度和谈判策略由 Game Core 预先确定。LLM 负责通过自然对话、询问重点、物件反应和议价语言逐步表现这些状态，不得直接泄露完整标签，也不得临时改变预算或购买条件。

买家初次只表达 Game Core 授权的宽泛购买方向。具体用途、品质要求、真实预算、预算弹性和急迫度需要在授权后逐步表达；表达不完整不等于故意欺骗，LLM 不得自行补全或下定性结论。

等待队列中的客人尚未进入交互时，LLM 只能依据 Game Core 授权提示“仍有客人在等待”，不能提前描述其具体人数、身份、买货或卖货来意、需求或到访顺序。

全日买卖顺序由 Game Core 决定。普通情况下最多连续 2 名同类客人；剧情或经营主题允许连续 3 名时，LLM 只能表达已经存在的例外，不能为了叙事连贯自行增加客人、改变身份或调整队列。

标准营业日是否已经满足至少 1 名判断挑战客人的要求，由 Game Core 在生成队列时验证。LLM 不接收需要面向玩家展示的“判断挑战”标签，也不能自行设定挑战答案或为了制造反转新增矛盾。它只根据 Game Core 授权的客人状态、器物线索、可透露条件和不确定性，通过自然对话、反应或内心独白表达玩家实际获得的信息。

普通标准营业日的判断挑战数量为 1～2 名；教学日和明确恢复日允许为 0 名；重要剧情日最多为 3 名并需要预定义例外。该数量对 LLM 只是既定内容上下文，不是可以通过生成文本改变的叙事参数。

重要剧情节点由设计者预先编排并由 Game Core 根据条件触发。LLM 可以表现已授权的剧情客人、消息、回访和爷爷线索，但不得为了让每个营业日都有剧情而自行创造事件。剧情可以隔数日出现，也可以在关键阶段连续出现。

纯经营日的经营主题由 Game Core 选择。LLM 可以根据主题生成开场氛围、传闻和与当天来客状态一致的谈话表达，但不得自行决定主题、改变其权重、补充未授权的市场事实，或把模糊趋势说成确定的赚钱机会。来客、器物和交易结果仍由 Game Core 决定。

经营主题可以包含世界驱动与玩家驱动来源。对于玩家驱动主题，LLM 只能表达已公开陈列、历史成交、类别口碑、NPC 关系或已传播事件，不得泄露隐藏库存、未发现的真假问题或未传播事实。相关口碑既可能带来合适客人，也可能吸引试探、抬价或其他风险，具体结果由 Game Core 决定。

普通交易产生的对外信号由 Game Core 累积。LLM 不得因一笔普通成交就宣告稳定口碑，也不得自行认定重要 NPC、高价值交易或重大事件已经获得立即影响资格。Game Core 确认主题资格和目标营业日后，LLM 才能表达相应传闻、关注或人物反应。

类别口碑内部数值和阶段门槛不提供给 LLM。Game Core 只提供当前模糊阶段、已授权的变化方向和可公开原因，LLM 据此生成开场、结算或 NPC 对话反馈。LLM 不得推算精确进度或承诺玩家再完成若干交易就会进入下一阶段。

类别口碑、全局信誉和 NPC 关系由 Game Core 分别提供。LLM 应使用不同语言表现三者：类别口碑体现某类器物上的专业与经营名声，全局信誉体现店铺是否可靠和诚信，NPC 关系体现具体人物的信任与态度。LLM 不得把单项结果扩大为全市场评价或所有人物的共同反应。

全局信誉内部值与阶段门槛不提供给 LLM。Game Core 只提供“声誉受损、尚无定论、口碑稳定、值得信赖”中的当前阶段、变化方向和可公开原因；LLM 可以通过市场传闻、店铺状态和客人态度表现，但不得推算精确进度。

NPC 关系内部值与阶段门槛不提供给 LLM。Game Core 提供“防备、生疏、熟悉、信任、深交”中的当前阶段、人物性格、当前立场和获授权的重要记忆；LLM 负责将同一机械阶段表现为符合人物的语言与行为。LLM 不得让阶段覆盖具体记忆、承诺、冲突或利益条件，也不得承诺关系再提升若干次就必然解锁事件。

玩家暂时切出当前客人交互时，LLM 进入等待状态，不在后台自行补写对话或推进 NPC 决策。玩家点击当前客人的头像、柜台卡片或等价入口返回后，LLM 根据 Game Core 保存的对话历史、已公开信息、耐心和交易阶段继续交互，不得把界面切换解释为新的会面或重新初始化客人。

当玩家推荐库存物件时，系统先自动展示由 Game Core 提供的物件具体类别，LLM 再帮助生成基于授权事实的推销表达。若物件只是弱匹配，玩家不必使用固定话术主动披露年代或价格偏差，但 LLM 不得将其说成完全匹配或改变物件类别。若玩家明确选择隐瞒或误导性的销售行为，LLM 可以表现该已选择的行为，但必须经过 Parser 和 Game Core 校验，不得自行判定成功、改变事实或决定买家最终接受结果。

玩家的价格判断、目标售价和报价属于销售表达或谈判立场，不因与市场估值不同就自动成为错误陈述。LLM 可以表现玩家选择的价格立场，但对年代、来源、真伪等客观属性的错误陈述，必须由 Parser 和 Game Core 识别与结算，不能由 LLM 自行认定后果。

 交易完成时，LLM 不应主动揭示或处罚玩家对客观属性的错误陈述。只有 Game Core 在后续场景中判定相关错误被真实发现后，LLM 才可以表现 NPC 反馈、信誉影响或学习反馈；第一版不在交易当下强行区分玩家正常误判和故意欺骗。玩家可以在问题发现后尝试解释、请求暂缓转卖、提供补充信息或利用已有关系进行有限干预，但每个传播圈层阶段最多一次主要干预，具体代价由事件规则决定，V1 不再预设为时间或日程成本。干预是否成功、是否延缓传播和是否产生新增影响由 Game Core 决定，LLM 只负责表现已结算结果。

后续发现事件中，Game Core 暂用普通客人、懂行买家或相关 NPC、专业鉴定人三个发现能力层级，并将问题严重程度分为轻微、严重、极严重三档。同一物件的多个问题分别判定，LLM 只能依据 Game Core 本次确认被识别的问题表现观察、疑问和反馈，不能因一个问题被发现就自动揭示其他隐藏问题。对于同一个问题，LLM 只能依据 Game Core 已结算的基础后果或新增影响生成反馈，不能重复表现同一基础惩罚。传播范围暂分为个人关系圈、行业圈、公众/市场圈，LLM 不能自行把反馈表现为已经进入更大圈层。LLM 不能自行判定某个发现者已经识别错误，也不能自行根据发现者层级生成是否处罚或后果强度。成交价格不参与发现判定，只在 Game Core 判定问题已被真实发现后参与影响结算。原买家身份由 Game Core 提供，V1 暂分为普通买家、懂行买家或行业相关 NPC、有行业影响力的买家；发现后是否发酵及其程度由 Game Core 根据问题严重程度、假货成交价格、买家身份、交易关系和传播范围结算。

买货交谈使用与卖货交谈相同的耐心结算框架，但由 Game Core 单独维护买家的最终选择阶段。进入该阶段后，LLM 只能表现买家在已看过物件中的最后决定、最后报价或离店反应，不能继续开放新的推荐机会。

## Identification Inner Monologue

鉴定反馈可以包含玩家根据当前经验产生的内心独白。Game Core 必须先提供：

- 数值化的真品可能性
- 玩家已经发现的线索
- 允许表达的不确定性
- 是否已经发现足以明确判假的瑕疵

LLM 只负责将这些授权信息表达为自然的内心判断。LLM 不得自行增加线索、改变概率、把概率性判断说成确定事实，或泄露 Game Core 保存的真实真伪。

内心独白是表达层输出；重新生成文本不得改变任何权威状态。

当 Game Core 因新线索或玩家主动重新查看物件而更新鉴定概率和授权线索时，LLM 可以生成新的内心独白。能力成长本身不会触发后台生成；只有玩家实际重新查看、重新鉴定或推荐物件时才更新表达。

## Dialogue Action Interpretation

交谈耐心按对话行为而不是玩家消息条数结算。对于玩家自由文本，LLM 可以输出结构化的候选行为分类，例如普通回应、必要澄清、新主题追问、重复追问、施压、质疑、指控或基于已有线索追问。

候选分类必须经过解析和校验，再由 Game Core 按规则结算耐心。LLM 不得直接扣除耐心，也不能仅因玩家发送了一条消息就认定产生消耗。普通回应、确认和必要澄清通常不消耗；重复、施压或指控通常消耗更多；具体分类边界与消耗值尚未确定。

道歉、解释或主动退让可以被分类为候选挽回行为，但单次交互最多触发一次有效尝试。Game Core 决定 NPC 是否接受和实际恢复量；寒暄、夸奖或重复友好表达不能被解释为可循环恢复耐心。
