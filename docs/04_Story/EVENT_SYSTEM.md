# Event System
事件可由 NPC 关系、资金、知识、过去行为、经历、成就和当前世界状态触发。V1 事件主要通过来到店内的客人、器物、信件、电话、传闻、旧交易回访和爷爷留下的记录呈现。拍卖、拜访 NPC、正式授课、行业活动及其他店外活动保留为 Post-V1 候选，不进入当前核心营业流程。

重要故事阶段主要由条件组合推进，不暂定固定日历，也不要求每个营业日必然发生剧情。剧情节点可以隔数日出现，也可以在关键阶段连续数日发生。重要剧情节点由设计者预先编排，常规经营案件由 Game Core 生成或选取，LLM 只能根据权威状态表达事件和人物对话。事件生成与 LLM 的边界见 [[LLM_DESIGN]]、[[AI_BOUNDARIES]]。

没有重要剧情节点的纯经营日使用一个当日经营主题维持内容差异。经营主题不是必须推动故事的事件，而是对当天候选来客、器物类别、交易动机、市场话题或氛围的受控权重调整。剧情日也可以使用兼容主题，但主题不得覆盖剧情节点的明确条件或改变已经确定的事件结果。具体主题库、选择条件、重复限制和影响强度尚未确定。

经营主题可以由世界状态和玩家已经对外形成的状态混合产生。世界来源包括市场趋势、城市传闻、行业事件、季节性需求和剧情阶段；玩家来源包括公开陈列、历史成交表现、类别口碑、NPC 关系和已经传播的事件结果。Game Core 只能使用世界中的人物有可能知道的信息建立玩家驱动主题，不能根据隐藏库存、尚未被发现的假货或未传播事实生成外界反应。

普通公开交易通过累积对外信号逐步形成主题来源，不在单笔成交后必然改变次日来客。重要 NPC 的公开成交、相对当前经营层级显著的高价值交易和已经公开传播的重大事件可以跳过普通累积过程，直接成为下一个尚未生成营业日的主题候选。是否实际选中及如何与其他来源组合仍由 Game Core 结算；已经生成的当日安排不得被追溯修改。

事件可以依据 Game Core 保存的精确类别口碑判断触发条件，但对玩家只反馈“尚无名气、偶有人提起、逐渐形成口碑、在相关圈子里受到认可”四个阶段。事件文本不得泄露具体数值、门槛或距离下一阶段的剩余进度。

事件影响需要分别指向类别口碑、全局信誉或具体 NPC 关系。类别相关的公开专业表现可以影响对应类别口碑；涉及店铺可靠性或诚信并传播到更广范围的事件可以影响全局信誉；直接发生在具体人物之间的行为可以影响该 NPC 关系。一项变化不自动推出另外两项变化，同一事件是否影响多个状态必须有明确的传播与因果条件。

事件可以依据全局信誉的精确内部值判断条件，但面向玩家只能使用“声誉受损、尚无定论、口碑稳定、值得信赖”四个阶段及获授权的变化原因，不得泄露具体数值与门槛。

事件可以依据 NPC 关系的精确内部值与具体记忆共同判断条件，但面向玩家只显示“防备、生疏、熟悉、信任、深交”五个阶段和人物化反馈。高关系阶段本身不能替代事件要求的承诺、共同经历、利益条件或特定记忆。

剧情或特殊客人默认占用上午或下午 2～3 名标准来客中的一个名额，并可根据其权威来意替代同类常规客人。只有被 Game Core 明确标记的重要剧情例外可以突破单阶段 2～3 名或全日约 4～6 名的常规总量。预约、失约和日程冲突不属于 V1 事件规则。

剧情或经营主题可以显式要求连续出现 3 名同类客人，作为普通“最多连续 2 名买家或卖家”规则的受控例外。该例外必须由事件或主题数据预先声明，并由 Game Core 在生成全日队列时验证；LLM 不能因叙事表达临时重排队列。

除教学日或明确的经营恢复日外，标准营业日的来客组合至少包含 1 名隐藏的判断挑战客人。剧情节点、经营主题或后果回访中的客人只要具备预先定义的判断来源、可发现线索、相关玩家行为和差异结果，就可以同时满足该名额，不需要额外增加来客。判断挑战可以来自说法与器物线索不一致、真诚但错误的认知、隐藏需求或预算、弱匹配推荐，以及高机会与高风险并存等情况；它不等同于诈骗事件。具体挑战标签不向玩家公开。

普通标准营业日安排 1～2 名判断挑战客人，并保留足够的常规经营客人作为节奏对比。教学日和明确的经营恢复日允许为 0 名；重要剧情日确有需要时最多可以安排 3 名，但事件数据必须显式声明该例外及原因，Game Core 负责验证，LLM 不能自行提高数量。

Game Core 在生成营业日时必须验证判断挑战拥有至少一项玩家有机会发现的有效线索。线索可以受到知识、经验、提问和观察方式限制，也不保证得出完全确定的结论，但事件不能把玩家置于无证据猜测或无条件强制失败中。LLM 只能表达已经授权的线索、隐瞒和不确定性，不能为了制造戏剧性临时创造新的矛盾或改变挑战答案。

玩家售出的假货，或玩家对年代、来源、真伪等客观属性作出的错误陈述，可能在二次倒卖、被其他 NPC 看货或类似后续场景中被真实发现。物件的多个问题分别判定是否被识别，一次事件只反馈本次被识别的问题，未被识别的问题继续隐藏；本次影响判定只使用本次实际被识别的问题，不提前按隐藏问题的真实严重程度产生后果。同一个问题的基础后果只结算一次；后续发现只有在带来新的传播圈层、新的关系对象或新的事件条件时，才可能产生新增影响。传播范围暂分为个人关系圈、行业圈、公众/市场圈，进入更大圈层不是必然结果。玩家可以在问题发现后通过联系买家解释、请求暂缓转卖、提供补充信息或利用已有关系尝试阻止或延缓传播，但不自动撤销交易且不保证成功；每个传播圈层阶段最多进行一次主要干预，具体代价由事件规则决定，V1 不再预设为时间或日程成本。Game Core 根据关系状态、玩家提供的信息和事件条件结算干预结果。Game Core 可以据此进入 NPC 反馈、行业口碑传播、关系后果和学习反馈的影响判定，但发现本身不保证必然引发负面发酵；发酵程度由问题严重程度、假货成交价格、买家身份、交易关系和传播范围决定。V1 的买家身份暂分为普通买家、懂行买家或行业相关 NPC、有行业影响力的买家，分别对应较小、中等和较大的传播潜力，但不代表必然触发对应事件。交易完成时不立即揭示或处罚，也不在第一版自动区分玩家正常误判和故意欺骗。事件不得自动撤销已经完成的普通交易。

后续发现者暂分为三个能力层级：普通客人、懂行买家或相关 NPC、专业鉴定人。层级只表示相关发现能力的范围，不直接决定后果轻重，也不保证必然发现；Game Core 还需要结合物件问题的明显程度、可观察线索和具体事件情境结算。问题严重程度暂分为轻微、严重、极严重三档。成交价格不参与发现判定，只在问题被真实发现后参与影响结算。后果强度主要由问题严重程度、假货成交价格、买家身份、交易关系和传播范围决定；买家身份层级影响传播与发酵潜力，发现者能力层级只影响能否识别问题。

V1 标准范例是：玩家售出真实为假的物件，原买家之后准备再次转卖，请懂行买家或相关 NPC 看货；Game Core 判定是否发现问题，再根据问题严重程度、假货成交价格、买家身份、交易关系和传播范围判定是否发酵及其程度。该范例不代表每次售出假货都必然按相同顺序暴露或必然产生信誉处罚。
