# 剧情架构总览

> [!summary] 一句话故事
> 一个在大城市被裁员的年轻人回到故乡，接手已故爷爷留下的古玩店；玩家一面学习辨物、识人和做生意，一面替上一代补完没有写清的账，最终决定自己要把怎样的人与物写进人生的账本。

本页是剧情与任务设计的 Obsidian 总入口。它整理现有事实、文档关系和监督方法，不把尚未确认的长期主线、城市名称、爱情线或最终结局写成永久规则。

## 状态图例

- **Confirmed Existing Fact**：已由现有文档、决策或第一章规格明确；本轮只重排，不改写。
- **Review**：已经存在于第一章规格或原型，仍等待人工试玩与正式锁定。
- **Draft Framework**：用于组织创作与审阅的方法，不是游戏内永久规则。
- **Draft Proposal**：可讨论的方向；未经 Human Designer 确认，不得据此实现为权威规则。
- **Open Question**：信息不足；必须保留问题，不得用台词或实现偷偷定案。

## 已确认的故事地基

1. 主要舞台是尚未正式命名的 `X City`。
2. 玩家离开大城市、回乡接手爷爷留下的古玩店；裁员是返乡的现实导火索。
3. 长期故事通过经营、鉴定、交易、人物关系与器物线索逐步揭示爷爷的人生、人脉和未完成之事。
4. 爷爷不是全知的谜题设计者，也会有误判、难处与没有办完的手续。
5. 重大故事阶段由 NPC 事件、能力、资金、人脉、经历与成就的条件组合推进，不采用“到某一天自动播片”的单一推进。
6. 重要剧情由设计者预先编排；Game Core 检查条件并结算；LLM 只表达已授权事实。
7. 第一章《旧账未清》围绕“暂存旧物是否被误当库存”展开，详见 [[CH01_OLD_DEBTS]]。

## 叙事层级

```text
游戏主题：继承不是拥有，而是决定如何对待未完之事
└─ 长期主线：玩家的鉴宝人生 / 爷爷留下的关系与责任
   ├─ 篇章：一个能够阶段性回答的重大问题
   │  ├─ 主线任务：推进篇章证据与选择
   │  ├─ 人物线：改变对某人的理解、关系或承诺
   │  ├─ 器物线：围绕一件物的真伪、来源、流转或归属
   │  ├─ 经营线：让日常生意承载人物与主题
   │  └─ 后果线：让过去的交易在后来真正回响
   └─ 事件节点：在某次来访、信件、电话、传闻或记录中发生
```

## 每个故事单元必须回答

一个可进入制作的故事单元至少要回答：

- 谁想从玩家这里得到什么？
- 玩家眼下能看见什么，不能看见什么？
- 哪件器物、记录或行动可以检验说法？
- 玩家能作出什么真正不同的选择？
- Game Core 需要检查和修改哪些权威状态？
- 当下结果与后续回响分别是什么？
- 如果玩家暂缓、拒绝或错过，故事怎样继续而不伪造结果？

## 监督工作流

```text
Human Designer 确认主题/边界
→ 使用 [[QUEST_TEMPLATE]] 写任务规格
→ 核对 [[GAME_RULES]] 与 [[EVENT_SYSTEM]]
→ 将事实、人物认知、玩家已知、公共传闻分层
→ 人工审阅分支与语气
→ 才能进入数据与实现 Task
→ Game Core 验证状态，LLM 生成表达
→ 试玩后把偏差写回文档
```

> [!warning] 权威边界
> 本架构不会让 LLM 直接修改资金、物权、真伪、关系、剧情旗标或事件结果。任何故事选择的状态变更都必须由 Game Core 校验；未确认的提案不能因为已经写得好看就视为事实。

## 当前审阅重点

- 先确认 [[STORY_BIBLE]] 的母题与叙事承诺是否符合你想要的整部作品气质。
- 再确认 [[MASTER_STORY_ARC]] 的篇章功能是否合理；其中除第一章外均是槽位，不是已定剧情。
- 以 [[CH01_OLD_DEBTS]] 检验 [[QUEST_ARCHITECTURE]] 是否足以承载现有内容。
- 所有未决定事项集中进入 [[STORY_OPEN_QUESTIONS]]，避免散落在对白或原型数据里。
