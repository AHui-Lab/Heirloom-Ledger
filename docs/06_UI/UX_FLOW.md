# UX Flow
当前确认的玩家体验流：进入店铺 → 查看当日开场信息 → 接待上午来客 → 午间过场与自由查阅 → 接待下午来客 → 晚上闭店结算 → 进入下一营业日。

V1 不显示精确时间、倒计时或行动点。上午、午间、下午和晚上是依次进入的章节化流程节点；玩家现实中的阅读、思考和界面停留不推动流程。当前阶段的来客处理完毕后，界面才提供或自动执行下一阶段转换。

标准营业日的上午和下午各安排 2～3 名客人，合计约 4～6 名；5 名时由 Game Core 决定采用 2/3 或 3/2。界面不需要提前公布完整人数分布。当前交互期间只提示是否仍有客人在等待，不显示等待队列的具体人数、身份、买货或卖货来意、需求和到访顺序。

除教学日或明确的经营恢复日外，标准营业日至少包含 1 名判断挑战客人，但界面不显示“判断挑战”、难度、正确答案或特殊考题图标。玩家只能通过正常的器物观察、鉴定信息、交谈内容、NPC 反应和库存匹配反馈发现相关线索，不能因为 UI 标记而提前知道某名客人需要特别警惕。

普通标准营业日实际安排 1～2 名判断挑战客人，重要剧情日最多 3 名；这个数量及例外不需要在日程或结算界面公开。教学或经营恢复日没有判断挑战时，界面也不显示“今日无挑战”一类元信息。

纯经营日的开场应通过一段简短信息、市场传闻或环境表现提示当日经营主题。玩家可以感知某类来客、器物或话题可能更常出现，但界面不显示生成倍率、保证收益或“推荐买卖”的系统答案。剧情日是否显示独立经营主题由当天内容决定。

当经营主题受到玩家过去行为影响时，界面可以通过“最近几笔瓷器成交让店里有了些名声”等可追溯反馈建立因果感，但只能引用已经公开或传播的信息。界面不能暗示买家知道玩家的隐藏库存，也不能将玩家形成的类别口碑表现成必然有利的增益。

单笔普通成交后，界面可以给出轻微的口碑积累反馈，但不应立即宣告已经形成新的经营主题。重要 NPC 公开成交、高价值公开交易或重大传播事件获得立即主题资格时，可以提供更明确的影响提示；实际主题仍要等下一个尚未生成的营业日由 Game Core 选择后才展示。

类别口碑界面只显示四个模糊阶段：尚无名气、偶有人提起、逐渐形成口碑、在相关圈子里受到认可。不得显示精确数值、百分比进度条、阶段门槛或还需完成多少笔交易。阶段变化可以在开场、闭店摘要、市场传闻或 NPC 对话中反馈，不要求每次内部数值变化都弹出提示。

界面需要把类别口碑、全局信誉和 NPC 关系作为不同信息表达，避免统一显示成一个“声望”。类别口碑与器物类别关联，全局信誉在店铺层面反馈，NPC 关系在人物信息和具体对话中反馈。同一事件影响多个维度时，应分别说明已经公开的变化原因，但不显示未授权的精确内部值。

全局信誉界面只显示四个模糊阶段：声誉受损、尚无定论、口碑稳定、值得信赖。不得显示精确值、百分比、进度条、阶段门槛或距离下一阶段的交易次数。阶段变化可以通过店铺状态、开场、闭店摘要、市场传闻和普通客人的初始态度反馈。

NPC 关系界面只显示五个统一阶段：防备、生疏、熟悉、信任、深交，不显示精确值、百分比、进度条、阶段门槛或还需多少互动。人物档案可以同时记录玩家已经知道的重要共同经历和承诺，使玩家理解关系变化，而不是只看到孤立的阶段标签。不同 NPC 在对话中的实际表现应保持个性差异。

午间过场允许玩家自由查看库存、账本、历史交易、人物已公开资料和鉴定记录，并通过明确的“继续营业”入口进入下午。这些查看行为不产生时间或行动成本。

晚上界面用于闭店结算，汇总玩家当前有权知道的资金、库存、知识、经验、关系和交易变化，并可表现 Game Core 已触发的剧情余韵或下一日线索。界面不得在此提前揭示尚未被真实发现的假货或隐藏后果。

玩家可以从当前客人对话暂时切换到与本次判断相关的信息界面，再通过当前客人的可识别入口返回。该入口可以表现为人物头像、柜台卡片或柜台场景中的人物位置；返回后继续原有对话与交易状态，不重新开始交互，也不消耗耐心。

不同客人应具有足以区分当前交互对象的视觉表现，但 V1 不要求每名随机客人都拥有完全独立的手绘头像；具体采用头像变体、组合式人物、柜台场景或其他方案留待 UI Art Direction 决定。

外出、拍卖、正式学习、预约、耗时活动中断恢复和日程冲突不属于 V1 界面流程。店铺经营、收货、委托、鉴定和事件的具体界面、输入方式、信息隐藏规则和导航结构尚未设计。

卖货交谈不能无限持续。玩家追问会影响由 Game Core 管理的客人耐心。后台可以保存精确值，但界面不直接显示数字或进度条；玩家通过 LLM 生成的语气、反应以及模糊阶段提示理解耐心变化。具体阶段数量、命名和视觉形式尚未确定。

耐心不按聊天消息数量扣除。普通回应、确认与必要澄清不应因为增加一条消息而惩罚玩家；系统需要先识别并校验实际对话行为，再反馈态度变化。

耐心耗尽后，界面和 NPC 对话需要清楚表现已经进入最终报价阶段：新的调查追问不再有效，但玩家仍可报价、进行必要的最后议价或放弃。若玩家继续拖延并导致 NPC 离店，必须提供明确的离店反馈。

玩家冒犯 NPC 后可以在单次交谈中尝试一次道歉、解释或主动退让。界面不承诺挽回成功，也不显示精确恢复值；NPC 的回应和模糊态度阶段需要清楚反馈是否被接受。重复寒暄或夸奖不能持续恢复耐心。

买货客人使用相同的耐心框架。耐心耗尽后，界面需要表现买家进入“最终选择阶段”：新的调查问题和库存推荐不再有效，但买家仍可在已经看过的物件中作出最后决定、提出最后报价或离店。

买家公开器物类别、约略价格和年代后，库存界面可以依据物件属性和当前市场估值，对符合公开条件的物件进行高亮或优先展示。初次匹配不依据玩家收购价或尚未提出的最终报价；玩家提出报价后，界面可以显示报价与买家预算的模糊匹配。该提示只表示机械匹配，不应替玩家判断真伪、利润、买家真实偏好或最终应出售的物件；具体高亮样式和匹配等级尚未确定。

年代匹配应允许至少三种模糊结果：完全落在买家范围内、部分接近或相邻、明显超出范围。界面需要让玩家知道这是需求匹配，不是对物件绝对年代的确认。

类别高亮应支持层级关系：买家提出父类时显示其子类物件；买家提出具体子类时优先显示精确子类，同父类其他子类可以弱高亮；不同大类不高亮。类别本身是物件的确定属性，但界面仍需要区分匹配提示与真伪、年代、品相和价值判断，不能让高亮看起来像自动推荐。

如果没有完全匹配的库存，界面应明确提示这一事实，同时保留弱匹配候选，而不是显示空列表。玩家可以自行选择弱匹配进行介绍和推销；界面应让玩家知道这是偏离部分需求的选择，并显示物件的确定具体类别。完全不同大类或明显偏离需求的物件不进入第一版常规推荐列表。

玩家选择推荐弱匹配时，物件介绍必须使用其确定的具体类别；玩家可以通过对话主动推销该物件，不必使用固定话术主动披露年代或价格偏差，但界面或对话表现不能把弱匹配伪装成完全匹配。买家是否被说服、接受或拒绝，仍由 Game Core 结算。界面应区分“玩家看到的匹配偏差提示”和“玩家必须对买家说出的事实”。

玩家选择某件物品进行推荐后，系统自动在物件介绍卡或对话起始信息中显示其确定具体类别，玩家不能通过自由文本省略或改写。玩家仍可在类别事实之后自由组织推销内容；年代和价格偏差不要求使用固定话术主动披露。

界面可以同时显示 Game Core 的市场估值、玩家自己的价格判断和当前谈判报价，但不应把三者差异直接标成“说谎”。年代、来源、真伪等客观属性的明确错误陈述，是否构成误导或欺诈，留待后续规则决定。

交易完成时，界面不立即揭示或处罚玩家对年代、来源、真伪等客观属性的错误陈述。只有后续场景真实发现相关错误时，才表现信誉、口碑、关系或事件后果；第一版不在交易当下强行显示玩家是误判还是故意欺骗。问题发现后，界面可以提供联系买家解释、请求暂缓转卖、提供补充信息或利用关系沟通等有限干预选项；每个传播圈层阶段最多提供一次主要干预机会，具体代价尚未确定，且必须由 Game Core 返回成功、失败或延缓结果。

后续发现事件暂采用普通客人、懂行买家或相关 NPC、专业鉴定人三个发现者层级。界面应表现发现者的身份或专业程度以及已经确认的错误，但不能在检查前直接告诉玩家该物件一定会被发现，也不能把能力层级显示成绝对成功率。一次事件只展示本次被发现的问题，不自动展示其他隐藏问题。发现者层级只表示发现能力，不应直接显示为处罚强度；成交价格也不应被显示为发现概率的直接依据。被发现后也不保证必然产生信誉或口碑影响；传播范围暂分为个人关系圈、行业圈、公众/市场圈，界面应区分新的传播或关系影响与已经结算过的基础后果。同一问题后续再次被发现时，不能重复展示同一基础惩罚。原买家身份暂分为普通买家、懂行买家或行业相关 NPC、有行业影响力的买家，是否发酵及程度还取决于问题严重程度、假货成交价格、买家身份、交易关系和传播范围。

鉴定反馈同时向玩家提供真品概率，以及基于当前已发现线索生成的玩家内心独白。真品概率由 Game Core 决定，以 `1%–99%` 的整数显示，不含小数，也不显示 `0%` 或 `100%`。发现决定性瑕疵时退出概率模式，单独显示“判定为假”。内心独白用于解释判断依据和不确定性。

主动鉴定时，有意义的新线索会更新概率和内心独白。库存物件不在后台自动刷新；玩家重新查看、重新鉴定或向买家推荐时才更新。界面需要保留并区分购入时判断与当前判断，具体布局尚未确定。

## 交谈与交易界面层级

交谈界面采用“对话优先”的三层结构：顶部只常驻 NPC、关系阶段、当前物件及资料/判断入口；中部对话记录占据主要可用空间；底部常驻提问提示、自由输入和少量情境操作。会面资料、新手提问、私人判断详情和议价编辑器不得同时作为纵向常驻模块挤压对话记录。

本次会面的完整对话默认保留并允许回看，因为人物前后说法本身是玩家判断可信度的证据。界面提供“回到最新”而不是“隐藏历史，只留最近一句”；当玩家正在向上查看时，后续版本需要避免强制抢走滚动位置。

会面资料通过临时浮层显示，只整理玩家已经知道的公开信息。玩家界面不展示“本地资料授权”“人物记忆条数”等实现或调试语言。提问提示同样使用临时面板，关闭后不改变对话区高度与滚动位置。

新手提问使用符合当前身份、物件和交谈阶段的自然口语完整句，而不是“问来历”“问预算”等系统命令式标签。玩家点击普通提问后，内容先进入输入框供确认或修改，再由玩家发送；剧情节点中已经明确设计为选择行为的按钮仍按剧情规则直接执行。

正常交谈阶段不常驻显示金额输入框。玩家点击“开始议价”，或者 Game Core 已将交谈推进到必须报价的阶段后，才展开整数报价编辑器；谈妥后仍需单独确认钱货交割。结束会面与提出价格使用不同的视觉优先级，避免误操作。

产生新的私人判断时，界面只在当前器物附近短暂显示内心提示，随后自动收起；顶部“判断”入口保留一个未读圆点。玩家打开当前物件详情后清除该物件的未读标记。完整概率、线索和历史判断仍归档在物件详情中，不长期占据人物对话区。
